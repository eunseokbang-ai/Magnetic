# 드론 자력탐사 자료 처리 프로그램

드론으로 취득한 자력탐사 자료를 업로드해 필터링, 측선 판별, 일변화/IGRF 보정, 그리딩, RTP/RTE/AS/1VD 파생 그리드까지 처리하는 웹 애플리케이션입니다.

## 구성

- `backend/` — FastAPI 처리 서버 (필터, 측선 자동판별, 일변화 보정, IGRF, 그리딩, FFT 변환)
- `frontend/` — React + Leaflet 지도 UI (업로드, 파라미터 조정, 지도 표시, 수동 측선 편집, 그리드/파생그리드 표시)

## 기능

1. 드론 자력 취득 파일 로딩 — 여러 비행 파일을 동시에 선택하면 하나로 합쳐 처리 (Date/Time/Lat/Lon/Mag 등 컬럼 자동 인식, GGA 전용 필드 시간축 보간)
2. 일변화(베이스 자력계) 자료 로딩 — 여러 로그 파일 동시 업로드 지원. 두 가지 형식을 자동으로 인식합니다: (1) 헤더 없는 쉼표구분 CSV(한글 오전/오후 12시간제, 행마다 날짜 포함), (2) 공백구분 "시 분 초 X Y Z 총자력" 하루 전체(1초 간격, GPS 시각만 있고 파일 내 날짜 없음) 텍스트 — 이 경우 파일명에 포함된 YYYYMMDD 날짜(예: `cyg202607151s.txt` → 2026-07-15)를 자동으로 읽어옵니다. 마지막 열(스칼라 총자력)은 X/Y/Z로부터 재계산하지 않고 그대로 사용합니다(실제 장비에서 별도 스칼라 센서로 측정한 값이라 X/Y/Z로 계산한 값과 정확히 일치하지 않는 것이 정상입니다).
3. 저주파 통과 필터 (Butterworth, 영위상 filtfilt)
4. 이착륙·터닝구간 등 비측선 자료 자동 판별/제거 (측선 방향 허용오차, 터닝 여분 구간(m) 설정 가능). **IMU 흔들림(스웨이) 검출**(기본 켜짐) — 자이로/가속도 컬럼이 있는 포맷(Geometrics MagArrow 등)에서 센서가 비정상적으로 흔들리거나 회전한 구간을 자동 검출해 함께 제외 (지상 대비 드론 자력탐사 비교 사례에서 측선 줄무늬의 주원인으로 지목된 헤딩 오차/센서 스웨이를 원본 자료 단계에서 직접 처리)
5. 일변화 보정 + IGRF 보정 (자력이상 = TMI - IGRF), 베이스 로거 시계 오프셋 보정 지원. **헤딩효과 캘리브레이션 보정**(기본 켜짐, 나침반 컬럼이 있는 포맷에서만) — 저경사도 구역에서 여러 자세로 짧게 비행한 별도 캘리브레이션 파일을 업로드하면, 센서 자세(헤딩)에 따른 판독 오차를 모델링해 흔들림으로 제외되었을 자료도 보정해 살립니다 (Zhang et al. 2022, *The Leading Edge* — Geometrics MagArrow 개발사 논문 기법). 별도 캘리브레이션 비행이 없으면 **측선 자체의 턴(방향전환) 구간을 자동으로 캘리브레이션 자료로 활용**(기본 켜짐, 제조사 지침의 "턴 구간이 보통 가장 좋은 캘리브레이션 자료" 권고 반영). 교차검증 기반 **캘리브레이션 품질 검증**(PASS/FAIL, 기준값 조정 가능)과 측선-캘리브레이션 헤딩 범위 불일치 경고를 함께 제공
6. 위치별 자력값(TMI/이상) 컬러 지도 표시
7. GUI 지도에서 측선 체크박스 또는 폴리곤/사각형 드래그로 추가 수동 제거 — 반대로 자동 판별이 잘못 제외한(비행 흔들림 등) 구간도 "포함(복원) 모드"로 영역을 그려 되살릴 수 있음, "수동 편집 모두 되돌리기"로 완전 자동 상태로 일괄 복귀
8. TMI 값 hover 표시 및 통계(min/max/mean/std)
9. 그리딩 (verde block-mean + 원본 셀(nearest, 기본/빠름)·선형·큐빅·스플라인 보간 선택 가능, 측선 간격 기반 자동 보간 반경으로 측선 사이 공백 최소화). **측선방향 평활화**(기본 켜짐)로 측선 내 자료 간격(보통 1m 내외)이 측선 사이 간격(보통 수십~수백 m)보다 훨씬 촘촘해서 생기는 측선 방향 줄무늬(코러게이션)를 억제 — 어떤 보간 방법을 쓰든 남아 있던 미세한 주름을 완화
10. RTP / RTE / 1VD / AS 파생 그리드 (Blakely 1995 방식 FFT 필터, 직접 구현)
11. 배경지도 (OSM, Esri 위성, Google 위성) — Leaflet 레이어 컨트롤로 전환
12. 헤딩(비행방향) 오차 보정 — 캘리브레이션(figure-8) 비행이 없을 때, 인접한 반대방향 측선 쌍 중 국지적 변화가 적은("조용한") 지점들을 찾아 방향별 평균 오프셋을 추정하고 측선별로 레벨링
13. 컬러맵 선택 (Viridis/Plasma/Turbo/RdYlBu/RdBu/Spectral/Grayscale/**Geosoft Rainbow**) 및 표시 범위(min/max) 수동 지정 — 특정 구간(예: 1000~2000nT)만 확대해서 색상 대비를 높여 볼 수 있음
14. 대용량 자료(수십만 포인트)에서도 매끄러운 지도 렌더링 — 포인트마다 개별 마커를 만드는 대신 캔버스에 직접 그리는 방식이라 색상/값 필드 등 옵션 변경 시 즉시 재도색됨
15. 그리드/파생그리드 위에도 측선(포인트) 레이어를 겹쳐 표시 가능(토글), 그리드 오버레이 불투명도 슬라이더 조절
16. 지도에 측선 번호 라벨 표시 토글 — 수동 편집 시 어느 측선이 몇 번인지 바로 확인 가능
17. 좌표계가 내장된 GeoTIFF(지질도 등 참조 자료) 업로드해 배경지도 위에 중첩 표시 — 여러 장 추가 가능하며 각각 표시여부/불투명도/쌓임순서(위·아래 이동) 조절
18. **힐쉐이드(음영기복) 표시** — 그리드/파생그리드 값 자체를 지형처럼 간주해 광원 효과를 입히는 Geosoft Oasis Montaj 스타일 표시 옵션(matplotlib `LightSource`). 완만한 값 변화도 입체감 있게 강조되어 미세한 경계·구조가 더 잘 드러남 — 광원 방위각/고도각/강조 정도 조절 가능
19. **그리드/파생그리드 GeoTIFF 내보내기** — 화면에 보이는 색상 PNG가 아니라 실제 값(nT 등)이 담긴 단일 밴드 float32 GeoTIFF로 다운로드해 Oasis Montaj/QGIS/ArcGIS 등 다른 프로그램에서 다시 열람·분석 가능
20. **3차원 자력 역산 (실험적)** — 사전 지질정보 없이 관측 자력이상만으로 지하 자화율(susceptibility) 분포 추정
    - 방법: Li & Oldenburg (1996) 심도가중 Tikhonov 역산 + Portniaguine & Zhdanov (2002) IRLS compact/focusing 재가중 (UBC-GIF MAG3D, SimPEG과 같은 계열의 사실상 표준 기법)
    - 정반응(forward) 계산: Fatiando a Terra의 `choclo` 직육면체 자력장 커널(numba 병렬화, 피어리뷰 검증됨)을 감싼 민감도 행렬 생성
    - 지형: DEM(GeoTIFF) 업로드 가능, 없으면 등고비행(일정 고도) 가정 하에 드론 GPS 타원체고에서 지형 추정 — "활성 셀(active cell)" 방식으로 지형 위 공기층 셀을 역산에서 제외
    - **파라미터 자동 설정**: 격자 크기는 측선 간격 기반, 탐사 심도는 자력이상 그리드의 방사평균 파워스펙트럼 기울기로 이상원 심도를 추정(Spector & Grant 1970)해 자동 산정 — 체크박스 해제 시 수동 지정도 가능. "더 상세한 역산"을 위해 격자를 촘촘히/레이어를 많이 잡을수록 실행 시간이 길어짐(최대 1~2분)을 허용하도록 관측점·활성 셀 상한을 상향
    - 결과 도시: 수평 섹션(깊이별 슬라이더, 지도 위 오버레이), 수직 섹션(자유선을 지도에 그리거나 동서/남북 고정 방향 + 위치 슬라이더로 즉시 조회, 크게 보기 패널), 3차원 이상대 뷰 — 세 가지 도시 모두 SI 값 하한/상한 범위 필터 지원
    - **3차원 이상대 뷰**(Plotly `isosurface`): 지정한 SI 범위(하한/상한)에 속하는 부분만 매끈하고 닫힌 하나의 "덩어리" 표면으로 렌더링 — 실제 역산 셀 크기가 크더라도 표시 직전에 더 촘촘한 격자로 삼중선형(trilinear) 보간해 부드럽게 이어 보이도록 처리(역산 결과 자체는 바뀌지 않음). 박스 상단에는 역산에 사용한 관측 자력이상/TMI 지도를 실제 지형 굴곡을 따라 입혀서(drape) 2D 자료와 3D 역산체의 위치 관계를 한눈에 볼 수 있음(체크박스로 켜고 끌 수 있음) — Oasis Montaj/VOXI류 소프트웨어의 일반적인 3차원 역산 결과 도시 방식을 참고
    - **결과 내보내기/불러오기**: 메쉬+모델 전체를 `.npz`로 내보내 나중에 처음부터 다시 역산을 돌리지 않고 그대로 불러와 단면/3D 뷰를 이어볼 수 있음. 활성 셀만 담은 (x, y, z, 자화율) 포인트클라우드 CSV로도 내보내기 가능해 ParaView/Voxler 등 다른 3차원 도구에서도 열람 가능. 수평 섹션도 GeoTIFF로 내보낼 수 있음
    - 격자 크기가 측선 간격보다 커지면(넓은 조사 영역에서 계산량 상한 때문에 발생 가능) 결과 요약에 경고 문구가 표시됨
21. **전체 프로젝트 저장/불러오기** — 업로드한 원본 자료, 처리 파라미터, 수동 측선 편집 상태, DEM, 역산 결과까지 하나의 `.zip`으로 저장하고 나중에 그대로 불러와 처음부터 다시 처리하지 않고 이어서 작업 가능. 저장 버튼 위 입력란에 파일명을 직접 지정할 수 있어(비워두면 `magnetic_project.zip`), 여러 프로젝트를 서로 다른 이름으로 저장해두고 필요할 때 원하는 것을 골라 불러올 수 있습니다.
22. **스파이크(이상치) 제거** — 필터 전에 이동중앙값(rolling median) + MAD(median absolute deviation) 기반 강건 통계로 울타리·차량 등 순간 잡음을 자동 검출/대체 (창 크기, 탐지 민감도 조절 가능, 제거 개수/비율 표시)
23. **타이라인(교차점) 레벨링 (선택 기능)** — 주 측선과 수직으로 비행한 검교정(타이) 측선이 있을 때만 활성화. 측선과 타이라인이 교차하는 지점에서의 값 차이를 이용해 측선별 레벨링 오차를 추정/보정 (타이라인이 없는 조사에서는 자동으로 비활성 상태 유지)
24. **등고선(등자력선) 오버레이 + 축척바 + 북쪽 화살표** — 그리드/파생그리드 값으로부터 등고선을 계산해 벡터 폴리라인으로 지도 위에 표시(간격 수동 지정 또는 자동 분할), Leaflet 축척 컨트롤과 고정 북쪽 화살표로 지도 판독성 향상
25. **오일러 디컨볼루션 (빠른 심도 추정)** — Euler's homogeneity equation을 그리드의 수평/수직 미분에 적용해 이상체의 대략적 위치·깊이를 빠르게 추정하는 표준 QC 기법. 구조지수(접촉면/암맥/파이프/구형) 선택, 탐색창 크기·깊이 불확실도 허용치 조절 가능, 결과를 깊이별 색상의 지도 마커로 표시 — 3차원 역산보다 훨씬 빠르지만 개략적인 결과
26. **히스토그램 균등화 색상 스트레치** — 기본 선형 스트레치 대신, 값의 실제 분포(순위)에 맞춰 색상을 재분배하는 옵션. 몇몇 극단적인 이상값이 나머지 자료의 색상 대비를 다 잡아먹는 상황을 완화
27. **GPS-자력계 시간 오프셋 보정** — 자력계 내부 필터링/통신 지연으로 위치와 자력값이 실제로 어긋나 있을 때, 알려진 지연시간만큼 위치 트랙을 재보간해 자력 샘플에 다시 매칭
28. **컬러 GeoTIFF 내보내기** — 값 그대로의 GeoTIFF(기존)에 더해, 화면에 보이는 컬러맵/힐쉐이드가 그대로 구워진 RGBA GeoTIFF도 선택적으로 내보내기 가능 (Google Earth 등에서 바로 열람할 때 적합)
29. **작업 단계 안내(진행 표시줄)** — 사이드바 상단에 업로드→처리→그리딩→(선택)고급분석의 진행 상태를 체크마크로 표시
30. **업로드 진행률 표시줄** — 대용량 CSV 업로드 시 실시간 진행률(%) 표시
31. **반응형 레이아웃** — 좁은 화면(태블릿/작은 창)에서는 좌우 패널이 슬라이드오버 형태로 접히고, 지도가 전체 폭을 차지 (넓은 화면에서는 기존과 동일)
32. **전문용어 툴팁** — TMI/IGRF/RTP/RTE/1VD/AS 등 약어에 마우스를 올리면 설명이 표시됨
33. **처리 보고서 생성(Markdown)** — 지금까지 적용된 모든 보정과 그 수치, 측선별 요약, 통계, (실행했다면) 3차원 역산/오일러 디컨볼루션 결과까지 정리한 보고서를 `.md` 파일로 다운로드

35. **AI 해석 도우미 (챗봇)** — 자력탐사 결과와 지질도 등 참조 레이어를 종합해 광물자원탐사·근지표 표적탐지 해석을 돕는 채팅 패널. 화면 스크린샷이 아니라 Claude API의 [tool use](https://docs.claude.com/en/docs/agents-and-tools/tool-use/overview)로 실제 프로젝트 자료를 조회(도구 호출)해 답변을 생성합니다.
    - 제공 도구: 측선/자력이상 통계 요약, 3차원 역산 자화율 요약, 오일러 디컨볼루션 결과 요약, 근지표 표적탐지 결과 요약(항목 36), 업로드된 참조 레이어(GeoTIFF) 목록 조회, 특정 위경도 좌표의 실측값 조회(가장 가까운 측점의 자력이상/TMI, 해당 위치의 역산 심도별 자화율, 참조 레이어 픽셀값을 한 번에 종합)
    - 참조 레이어 업로드(항목 17) 시 지도 표시용 이미지와는 별도로, 챗봇이 실제 픽셀값을 조회할 수 있도록 프로젝트에 원본 GeoTIFF 사본도 함께 보관합니다.
    - 자력탐사만으로는 암종·광종이나 근지표 표적의 정확한 종류를 특정할 수 없다는 점, 수치는 반드시 도구로 조회한 실제 값만 인용한다는 점, 표적탐지 맥락에서는 실제 위치 확인·처리에 EOD 등 전문 인력이 필요하다는 점을 시스템 프롬프트로 명시했습니다.
    - **배포 시 별도의 `ANTHROPIC_API_KEY` 환경변수가 필요합니다** — 이 앱을 실행하는 서버(백엔드) 환경에 설정해야 하며, Claude Code 세션 자체의 API 접근과는 무관한 별도 키입니다. 키가 없으면 채팅 시도 시 안내 메시지가 표시됩니다.
36. **근지표 표적탐지 (지뢰·불발탄·은닉 차량 등)** — 왼쪽 사이드바 상단의 "용도" 토글로 "🎯 근지표 표적탐지" 모드를 선택하면 활성화되는 별도 분석 기능. 넓은 지역의 완만한 지질체를 가정하는 광물자원탐사용 3차원 역산/오일러 디컨볼루션과 달리, 작고 국지적인 강자성 표적 하나하나를 찾아 위치·심도·상대적 철질량 크기를 추정합니다.
    - **방법**: 자력이상을 촘촘한 격자(기본 1m)로 만든 뒤, 국지적 극값(local maximum)만 후보로 고르고(완만한 지질 배경은 극값 자체가 없어 자동으로 제외됨) 각 후보를 실측 포인트에 대해 단일 유도자화 자기 쌍극자(magnetic dipole) 모델로 비선형 최소자승 피팅해 위치(x, y)·심도·쌍극자모멘트(A·m², 상대적 철질량 크기 지표)를 구합니다 — UXO/불발탄 자력탐사 문헌에서 표준적으로 쓰이는 "dipole fit" 기법입니다. 후보 크기(footprint)는 절대 진폭 임계값이 아니라 반진폭(half-amplitude) 폭으로 측정해, 강한 신호를 내는 큰 표적의 판정 반경이 부풀어 오히려 "넓은 지질 배경"으로 오분류되는 문제를 피합니다.
    - **용도 전환 시**: 격자 크기 기본값이 광물탐사용(10m)에서 표적탐지용(1m)으로 자동 전환되고, 3차원 역산/오일러 패널은 접힌 상태(고급, 필요시 펼침)로, 표적탐지 패널은 펼쳐진 상태로 바뀝니다.
    - **결과**: 표적 후보 목록(심도, 쌍극자모멘트, 크기등급, 첨두이상값, 적합도)을 표로 표시하고 지도 위에 마커로 겹쳐 표시(마커 크기는 모멘트 로그값에 비례). 처리 보고서(.md)에도 별도 절로 포함됩니다.
    - ⚠ **자력탐사만으로 표적의 정확한 종류(지뢰/포탄/전차/단순 고철 등)를 식별할 수 없습니다.** 쌍극자모멘트 기반 크기등급은 문헌상의 대략적인 order-of-magnitude 구간일 뿐 검증된 분류기가 아니며, 최소금속(low/minimal-metal) 물체는 자력 신호가 거의 없어 애초에 탐지되지 않을 수 있습니다. **실제 위치 확인·접근·처리는 반드시 EOD(폭발물처리반) 등 전문 인력이 현장에서 수행해야 합니다** — 이 기능의 결과만으로 안전을 판단하거나 접근해서는 안 됩니다.
    - 관측면을 평평한 기준면으로 가정하는 단순화는 오일러 디컨볼루션과 동일합니다 — 심도는 그 기준면 기준이며, 실제 매설 심도와는 드론 비행고도(AGL)만큼 차이가 있을 수 있습니다.
    - 격자가 지나치게 촘촘하고(격자 크기를 매우 작게, 조사 영역은 넓게) 예상 셀 수가 상한(4,000,000)을 넘으면 실행 전에 오류로 안내됩니다 — 격자 크기를 늘리거나 관심 영역만 남기고 재시도하세요.
37. **자료 품질검사(QC) 자동화** — 드론/베이스 CSV 로딩 시 중복된 시각(같은 파일 재업로드, 로거 중복 기록 등)과 비정상 좌표(위경도 범위 밖, GPS 미수신 시 흔한 (0,0) 값)를 자동으로 제거하고, 제거된 개수를 업로드 요약에 표시합니다.
38. **필터 종류 선택** — 기존 Butterworth 저역통과(영위상)에 더해 Savitzky-Golay(다항식 평활화, 이상체 봉우리 보존에 유리)와 이동평균 중에서 선택할 수 있습니다. Butterworth 선택 시, 드론 자료의 평균 비행속도를 기반으로 "이 정도 파장의 이상체는 보존하고 싶다"는 값을 입력하면 권장 차단주파수를 계산해 한 번에 적용하는 도우미도 함께 제공됩니다.
39. **좌표계 수동 지정** — 기본적으로 측선 중심 위치로 UTM 구역을 자동 감지하지만, 특정 EPSG 코드를 직접 지정할 수도 있습니다(예: 조사 영역이 UTM 구역 경계에 걸쳐 있어 자동 감지 결과를 다른 프로젝트와 맞추고 싶을 때). 실제 사용된 좌표계는 처리 요약에 EPSG 코드로 표시됩니다.
40. **파생 그리드 4종 추가**
    - **THDR(총수평미분)** — 자화 방향에 무관하게 이상체 경계에서 뚜렷하게 나타나는 수평 변화율 크기로, 접촉면·경계 파악에 RTP/1VD와 함께 참고할 수 있습니다.
    - **상방연속(Upward continuation)** — 지정한 높이만큼 더 높은 고도에서 측정한 것처럼 계산을 재구성해, 짧은 파장(얕고 좁은) 잡음을 광역 신호보다 훨씬 빠르게 감쇠시킵니다.
    - **추세면 제거(Detrend)** — 완만한 광역 배경을 다항식(1~3차)으로 최소자승 적합해 뺀 잔차만 표시해, 얕은 국지 이상을 광역 추세와 분리해 볼 수 있습니다.
    - **마이크로레벨링(디코러게이션)** — 측선과 나란한 방향, 측선 간격 규모의 파장을 갖는 줄무늬 잡음만 골라 파수영역 방향성 노치 필터로 완화합니다. 헤딩/타이라인 보정 후에도 남는 줄무늬가 있을 때 사용하는 표준 항공자력 처리 기법입니다(Geosoft 등 상용 소프트웨어의 decorrugation 필터와 동일한 개념).
41. **측선 프로파일 뷰** — "7. 수동 측선 편집"의 각 측선 목록에서 📈 아이콘을 누르면 해당 측선의 거리-값(자력이상/TMI) 그래프를 볼 수 있습니다. 제외된 포인트는 빨간 점으로 표시되어, 지도의 색상 패턴만으로는 알기 어려운 스파이크·드리프트·레벨링 오차를 측선 단위로 직접 확인할 때 유용합니다.
42. **XYZ(텍스트) 내보내기** — GeoTIFF에 더해, 그리드/파생그리드 결과를 경도·위도·값 3열의 공백 구분 일반 텍스트(XYZ)로도 내보낼 수 있습니다. GeoTIFF를 지원하지 않는 프로그램에서도 열람 가능합니다.
43. **처리된 포인트 전체 CSV 내보내기** — 위경도·로컬 좌표·자력이상·TMI·측선 번호·제외 여부까지 담은 전체 포인트 목록을 CSV로 다운로드할 수 있습니다.
44. **다중 장비 CSV/ASC 자동 포맷 감지** — 기존 일반(Geometrics MagArrow 호환) 포맷에 더해, 파일 헤더를 자동 인식해 MicroInfinity Mag(22열 CSV, TOW 기반), SENSYS MagDrone R1(TMI 컬럼 포함 CSV), SENSYS MagDrone R3 원시 로그(세미콜론 구분 이중 프로브), SENSYS MagDrone R3 ASC(1차 처리 결과물) 파일을 별도 지정 없이 업로드만으로 처리합니다. 인식된 형식은 업로드 요약에 표시됩니다.
45. **한국 좌표계(Korea Projection) 옵션** — 기본 UTM 자동감지 외에, KoreaUTM(EPSG:5179, GRS80 기반 한국 통합 좌표계), Korea2010(EPSG:5185~5188, 경도대별 벨트 좌표계), 국내 UTM(51N/52N) 중에서 선택할 수 있습니다. 국내 관공서·측량 표준과 맞추고 싶을 때 유용합니다.
46. **파생 그리드 확장 (Tilt/Theta/2VD/그래디언트 텐서)** — 기존 RTP/RTE/1VD/AS/THDR/상방연속/추세면제거/마이크로레벨링에 더해, 틸트각(Tilt Angle, 이상체 진폭 크기와 무관하게 경계에서 0을 지나감)·세타맵(Theta Map)·2차 수직미분(2VD)·1·2차 동서/남북/혼합 미분(dX/dY/dXX/dYY/dXY/dXZ/dYZ) 총 9종을 추가로 제공합니다.
47. **Surfer GRD/BLN 내보내기** — 그리드/파생그리드 결과를 Surfer 6 Binary Grid(.grd, DSBB) 형식으로, 지도에서 그린 영역을 Surfer Blanking File(.bln)로 내보낼 수 있어 Golden Software Surfer 워크플로와 바로 연동됩니다.
48. **Adaptive Hampel 스파이크 제거** — 기존 이동중앙값+MAD 방식에, 인접 샘플 기울기가 급변하는 구간(진짜 경사 신호일 가능성)에서는 창 크기를 자동으로 넓혀 비교하는 적응형 로직을 추가해 진짜 신호를 스파이크로 오판하는 것을 줄였습니다(켜고 끌 수 있음).
49. **최소곡률(Minimum Curvature) 격자화** — 기존 원본셀/선형/큐빅/스플라인에 더해, Golden Software Surfer의 기본 격자화 알고리즘과 동일한 Briggs(1974) 최소곡률 방식을 선택할 수 있습니다. 데이터를 지나는 매끄러운 곡면을 반복법(damped relaxation)으로 구해 잠재장 자료에 적합한 결과를 냅니다.
50. **반복(iterative) 네트워크 타이라인 레벨링** — 기존에는 타이라인을 완전히 고정된 기준으로 취급했지만, 새 옵션(기본 켜짐)은 측선과 타이라인의 보정값을 번갈아 재추정하며 오차를 양쪽에 고르게 분산하는 소규모 네트워크 조정을 수행합니다. 기존 방식(타이라인 고정)도 선택적으로 유지됩니다.
51. **PCA 자동 방향 검출 + 전용 비행경로 편집기** — 측선 방향 판별을 기존 진행방향 히스토그램 대신, 측점 분포의 주축(PCA)으로 검출하는 방식도 선택할 수 있습니다. 또한 "7. 수동 측선 편집"에서 "비행 경로 편집기 열기" 버튼으로 위경도 지도가 아닌 투영 좌표(미터) 평면에서 확대/축소하며 드래그로 영역을 제거(Cut)/복원(Restore)할 수 있는 전용 편집기를 제공합니다(DroneMagAdv의 FlightPathDlg 방식 참고).
52. **노이즈 QC (정규화 4th/8th difference)** — Near-Surface Geophysics Inter-Society Committee의 UAV 자력탐사 가이드라인이 표준 항공자력 노이즈 지표로 제시하는 정규화 4차/8차 차분을 측선별로 자동 계산해 처리 요약에 표시합니다. 다른 측선보다 눈에 띄게 노이즈가 큰 측선은 자동으로 플래그됩니다.
53. **지각적으로 균일한 Cubehelix 컬러맵** — 기존 레인보우 계열 컬러맵(Geosoft Rainbow 등)은 특정 색상 구간에서 지각적 대비가 낮아져 이상대가 가려지는 문제가 있는데(위 가이드라인이 구체적으로 지적), 이를 피하도록 설계된 Cubehelix(Green, 2011) 컬러맵을 컬러맵 목록에 추가했습니다.
54. **그리드 셀 크기 가이드 경고** — 가이드라인의 "셀 크기 = 측선 간격의 1/4~1/5" 권장 규칙에서 크게 벗어난 셀 크기를 지정하면(너무 성기거나 너무 촘촘함) 범례 아래에 경고를 표시합니다.
55. **반복측선(Repeatability) 분석** — 가이드라인이 권장하는 실측 노이즈 봉투 산출 절차: 같은 구간을 여러 번(왕복 포함) 비행한 별도의 테스트 비행 자료를 업로드하면, 반복 통과를 자동으로 그룹핑해 1/2/3-시그마 노이즈 봉투와 정방향-역방향 헤딩오차를 계산합니다("15. UAV 자력탐사 가이드라인 진단 도구" 패널).
56. **파워스펙트럼 진단 + 노치필터** — 측선 하나를 선택해 원시 자력신호의 파워스펙트럼(Welch)을 확인하고, 드론 모터 회전(~45-60Hz)이나 흔들림(~0.1-0.6Hz) 같은 특정 간섭 주파수가 피크로 보이면 한 번의 클릭으로 노치필터에 등록해 다음 처리 실행 시 제거할 수 있습니다.
57. **멀티스케일 엣지 검출 (Worming)** — 여러 상향연속 고도에서 총수평도함수(THDR) 능선을 추출해 지질 경계/구조선을 개략적으로 매핑하는 가벼운 도구입니다. 오일러 디컨볼루션보다 빠른 개관용이며, 지도에 상향연속 고도별로 색이 다른 점으로 표시됩니다.
58. **파일(타일) 간 레벨 불일치 자동 감지** — 서로 다른 시점/베이스 위치로 나눠 업로드한 여러 드론 CSV 파일 사이에 자력 이상값의 DC 레벨 차이(가이드라인이 지적하는 대표적 아티팩트 원인 - 베이스 위치 이동 등)가 있으면 처리 요약에 경고로 표시합니다.
59. **디코러게이션 규칙 안내 툴팁** — 측선방향 평활화/마이크로레벨링 파장 관련 입력란에 가이드라인의 필터 길이 권장 규칙(저역통과=타이라인 간격×2, 고역통과=측선 간격×2)을 안내하는 툴팁을 추가했습니다.
60. **Boxing 격자화 방법** — 기존 원본셀/선형/큐빅/스플라인/최소곡률에 더해, 가이드라인이 소개하는 "Boxing"(빈 셀에는 보간하지 않고 실측값이 있는 셀만 그 평균으로 채우는 방식)을 선택할 수 있습니다. 자료가 없는 구간을 억지로 채우지 않고 있는 그대로 보여주고 싶을 때 유용합니다.
61. **정규분포 색상 스트레치** — 기존 선형/히스토그램 균등화 스트레치에 더해, 값 분포를 정규분포로 가정하고 평균·표준편차 기반으로 색상을 배분하는 스트레치 옵션을 추가했습니다.
62. **샘플링 거리 히스토그램(QC)** — 측선 내 연속된 두 측점 사이의 실제 이동거리를 히스토그램으로 계산해 처리 요약에 표시합니다. GPS 순간 끊김(dropout)으로 특정 구간만 샘플 간격이 크게 벌어진 경우를 감지하는 가이드라인 권장 QC 지표입니다.
63. **폴리노미얼(1차) 타이라인 레벨링** — 기존에는 측선별로 상수(0차) 오프셋만 보정했지만, 새 옵션은 각 측선을 따라 선형으로 변하는 오차(1차 다항식)까지 함께 추정해 보정합니다. 타이라인이 2개 이상 있어 교차점이 남북으로 퍼져 있을 때 더 정확한 레벨링이 가능합니다(비반복 모드 한정).
64. **3차원 역산 자동 정규화(Discrepancy Principle)** — 정규화 강도를 수동으로 조정하는 대신, 예상 관측 잡음수준(nT)을 입력하면 역산 잔차(RMS)가 그 수준에 가까워지도록 정규화 강도를 자동으로 탐색합니다(UBC-GIF/SimPEG 방식의 discrepancy principle). 비음수 제약으로 인해 정규화-잔차 관계가 단조롭지 않은 구간까지 고려한 2단계(격자 탐색 후 이분탐색) 탐색과, 실제 IRLS 압축(compact) 재가중이 반영된 잔차 지형을 미리 한 번 추정(snapshot)해 탐색 목표로 삼는 보정을 적용해 신뢰성을 높였습니다.
65. **3차원 역산 심도별 해상도(민감도) 진단** — 민감도 행렬의 레이어별 평균 크기를 계산해, 측선 배치·비행고도상 실제로 잘 구속되는 심도와 그렇지 않은(민감도가 최상층 대비 5% 미만) 심도를 자동으로 구분합니다. 결과 요약과 수평 섹션 뷰 깊이 슬라이더에 레이어별 막대 그래프/경고로 표시되어, 깊은 레이어의 역산 결과를 과신하지 않도록 돕습니다.
66. **수직 단면 뷰 개선** — 기존의 단순 픽셀 이미지 대신, 실제 거리(m)·고도(m) 축과 눈금, 지표면 굴곡을 나타내는 선, SI 컬러바가 있는 제대로 된 도면으로 렌더링합니다. 또한 좌측 상단에 전체 조사구역 범위와 현재 단면의 위치(A–A')를 함께 보여주는 위치도(locator inset)를 추가해, 잘라낸 단면이 전체 조사지역 어디에 해당하는지 바로 확인할 수 있습니다.
67. **수평 섹션 뷰 실제 심도 표시** — 깊이 레이어 슬라이더가 이제 레이어 인덱스뿐 아니라 실제 고도(m)를 함께 보여주고, 얕음/깊음 양끝 고도값과 항목 65의 레이어별 해상도 경고도 슬라이더 옆에 함께 표시됩니다. 지도 범례에도 현재 표시 중인 슬라이스의 실제 고도가 나타납니다.
68. **SI 연속 컬러링 박스 단면(펜스 다이어그램) 3D 뷰** — 기존의 "임계값 이상만 표시하는 매끈한 덩어리" 뷰에 더해, 상단 수평면 + 4개 측벽 전체를 임계값 없이 하나의 연속 SI 컬러스케일로 보여주는 새 3D 표시 모드를 추가했습니다(발표용 3차원 역산 그림에서 흔히 쓰이는 색칠된 상자 스타일). 상단면의 깊이 레이어는 슬라이더로 바꿔가며 확인할 수 있고, 두 뷰(덩어리/박스단면) 사이는 버튼 하나로 전환됩니다.
69. **베이스 시간 오프셋 시/분/초 입력** — 기존 "초" 단일 입력 대신 시/분/초를 각각 입력할 수 있어, 몇 시간 단위로 어긋난 베이스 로거 시계도 정확하게(예: 1시간 23분 45초) 보정값을 계산할 필요 없이 바로 입력할 수 있습니다.
70. **이착륙 구간 자동 식별 + 숨김/보호** — 실제 이륙 지점부터 첫 측선 시작까지, 마지막 측선 종료부터 착륙 지점까지의 "이착륙 구간"을 자동으로 식별해 측선 편집기에서 기본적으로 숨기고, 제외/복원 영역 그리기의 대상에서도 제외합니다(켜면 다시 표시/편집 가능). 실수로 이착륙 구간을 측선 자료로 착각해 편집하는 것을 방지합니다.
71. **측선 내 일시적 이탈 구간 브릿징** — 바람 등으로 위치/헤딩이 순간적으로 측선판별 기준을 벗어나도, 경로 길이·직선 대비 우회 정도(직선성)로 볼 때 같은 물리적 측선이 명백하면 자동 제외하지 않고 그 구간을 이어 붙여(bridging) 측선을 끊기지 않게 유지합니다. 실제 턴(방향전환)/캘리브레이션 루프는 직선성 기준으로 구분해 여전히 제외됩니다.
72. **베이스(일변화) 자료 자동 QC + 원본/보정 비교 그래프** — 베이스 로거를 설치/회수할 때 흔들리며 기록되는 큰 진폭의 노이즈 구간을 자동으로 감지해 시작/끝에서 트림하고, 정착된 구간 중간에 있는 비정상적으로 튀는 값(스파이크)은 로버스트 통계(중앙값+MAD)로 검출해 주변 값으로 매스킹합니다(측선 despike와 같은 원리를 베이스 로그에 적용). 처리 요약과 "베이스 원본/보정 자료 그래프 보기" 버튼을 통해 원본과 보정 후 자료를 시계열 그래프로 겹쳐 비교할 수 있습니다.
73. **측선 프로파일 원본 vs 처리후 비교 + 왜곡 구간 수동 스무딩** — 측선 프로파일 그래프에 필터링(디스파이크+노치+저역통과) 전 원본 신호를 처리 후 신호와 겹쳐 표시해, 자료처리 과정에서 없어진(또는 없어져야 했는데 남은) 자료를 눈으로 확인할 수 있습니다. 지상 구조물(집, 건물 등)로 인한 왜곡이 보이는 구간은 그래프를 드래그해 선택한 뒤 "스무딩 적용" 버튼으로 제거할 수 있습니다 — 선택 구간 양쪽에 인접한 정상 구간 값들의 중앙값(단일 경계값이 아니라 몇 개 표본의 중앙값)을 기준으로 배경 수준을 추정한 뒤 그 사이를 직선으로 이어, 다이폴 형태로 솟았다 가라앉는 왜곡을 배경값과 매끄럽게 맞춥니다. 같은 기능을 지도에서도 사용할 수 있어, 참조 레이어로 드론 정사영상(orthophoto)을 업로드해 구조물 위치를 눈으로 확인하며 그 위에 영역을 그려 왜곡을 제거할 수 있습니다. "7. 수동 측선 편집" 패널에 적용 횟수와 함께 "↩ 실행취소"(가장 최근 1건만 취소)·"전체 되돌리기"(지금까지 적용한 스무딩을 모두 취소) 버튼이 있어, 결과가 기대와 다르면 언제든 되돌릴 수 있습니다. 이미 그리드를 생성해 지도에 표시해둔 상태였다면, 스무딩 적용/취소 직후 같은 설정으로 그리드를 자동으로 다시 만들어 보여주므로 지도가 갑자기 사라지지 않고 바로 결과를 확인할 수 있습니다.
74. **베이스 자료 없이 처리 진행 (지구자기장 일정 가정)** — 베이스(일변화) 자료를 측정하지 못했을 때, 일변화 보정 방식을 "베이스 자료 없음"으로 설정하면 지구자기장이 조사 기간 동안 일정했다고 가정하고 드론이 측정한 값을 그대로 사용해 다음 단계로 진행할 수 있습니다(수학적으로는 완전히 일정한 베이스 값으로 보정하는 것과 동일한 결과). 태양풍 등에 의한 시간에 따른 자기장 변화(일변화)는 보정되지 않는다는 경고가 함께 표시됩니다.
75. **INTERMAGNET 관측소 자료로 베이스 자료 대체** — 로컬 베이스 자료가 없을 때, 전 세계 지자기 관측소 네트워크인 [INTERMAGNET](https://intermagnet.org)의 공개 자료를 대신 활용해 일변화 보정을 할 수 있습니다. 로컬(측정 지역 고유)한 일변화까지는 반영하지 못하지만, 태양풍에 의한 지역/전지구적 자기장 변화는 인근 관측소 자료로 추정할 수 있습니다(일변화 보정은 베이스 값의 절대 수준이 아니라 조사 시간창 평균 대비 *변화량*만 사용하므로, 원거리 관측소의 절대 자기장 차이는 자동으로 상쇄됩니다). 두 가지 방법을 지원합니다: (1) intermagnet.org에서 직접 받은 IAGA-2002 형식 파일을 업로드 — 서버의 네트워크 접근 여부와 무관하게 항상 동작, (2) 관측소 코드(IAGA 코드)와 시작일·종료일을 입력하면 서버가 BGS INTERMAGNET Global Node에서 자동으로 받아옴 — 서버 배포 환경의 아웃바운드 네트워크 정책에 따라 막혀 있을 수 있으며, 이 경우 (1)번 방법을 사용하세요. 두 경우 모두 관측소명·위치·조사지역까지의 거리·자료 기간을 먼저 보여주는 미리보기 단계를 거친 뒤 "이 자료를 베이스 자료로 사용" 확인을 눌러야 실제로 적용됩니다.
76. **오프라인 배경지도 (지도 타일 미리 다운로드)** — 배경지도는 기본적으로 온라인 타일 서버(OpenStreetMap/Esri/Google)에서 실시간으로 받아오므로 인터넷 연결이 필요합니다. 조사 예정 지역이 미리 정해져 있다면, 사무실 등 인터넷이 되는 곳에서 그 지역의 지도 타일을 미리 받아 서버 디스크에 저장해두고, 현장에서 인터넷 연결 없이도 배경지도를 계속 사용할 수 있습니다. 우측 패널 "오프라인 지도" 섹션에서 지도 소스(OpenStreetMap 또는 Esri 위성 영상), 위경도 범위(현재 화면을 그대로 채우는 버튼 제공), 확대단계(zoom) 범위를 지정해 "용량 확인" 후 "다운로드 시작"을 누르면 됩니다. 받아둔 타일은 지도 레이어 목록의 "OpenStreetMap (오프라인 캐시)" / "Esri 위성 (오프라인 캐시)" 항목으로 계속 표시되며(이 앱 자체 서버가 캐시를 서빙하므로, 캐시에 있으면 브라우저가 외부 타일 서버에 접속하지 않습니다), 온라인 상태에서 이 캐시 레이어로 지도를 그냥 둘러보기만 해도 지나간 영역의 타일이 자동으로 캐시에 쌓입니다. 조사 지역처럼 좁은 범위 + 필요한 확대단계만 받는 것을 권장하며(한 번에 최대 5,000개 타일 제한), 이용약관 문제로 자주 바뀌는 비공식 Google 타일은 대량 다운로드 대상에서 제외했습니다(실시간 온라인 표시만 기존처럼 지원). *(참고: 개발 샌드박스 환경 자체의 네트워크 정책상 실제 타일 서버 접속을 이 환경에서 직접 검증하지는 못했습니다 — 표준 Slippy Map 타일 규격을 따르는 구현이며 모의(mock) HTTP 응답으로 캐시 저장/서빙 로직은 전부 테스트했으니, 실제 사용 환경에서 동작을 한 번 확인해 주세요.)*
77. **대용량 정사영상 폴더 연동 (사전 타일링)** — 수십 GB급 드론 정사영상 GeoTIFF를 "12. 참조 레이어"에 그대로 업로드하면 서버가 전체 래스터를 읽어 렌더링해야 해서 매우 오래 걸립니다. QGIS의 "래스터 → 타일 생성(XYZ)" 기능이나 GDAL의 `gdal2tiles.py`로 미리 확대단계별 타일 폴더(`0/`, `1/`, `2/`... 처럼 확대단계 숫자 이름의 하위 폴더 구조)를 한 번 만들어두면, "12. 참조 레이어"의 "대용량 정사영상" 항목에서 그 폴더의 전체 경로를 입력하고 "폴더 연동"을 누르는 것만으로 업로드·재렌더링 없이 그 폴더를 서버가 직접 읽어 즉시 배경 레이어로 표시합니다(타일 요청마다 파일 하나만 읽으므로 원본 크기와 무관하게 빠릅니다). 경로 입력란 옆 📁 아이콘을 누르면 이 프로그램을 실행 중인 컴퓨터 화면에 네이티브 폴더 선택 창이 떠서 마우스로 직접 골라 넣을 수 있습니다(브라우저 자체는 보안상 실제 파일 경로를 알려주지 않으므로, 서버가 대신 폴더 선택 창을 띄우는 방식입니다 - 화면이 없는 서버 환경에서는 대신 경로를 직접 입력하라는 안내가 표시됩니다). 타일 행 순서(XYZ 방식 = 0행이 북쪽, TMS 방식 = 0행이 남쪽, GDAL 기본 출력)는 폴더 안의 `tilemapresource.xml` 존재 여부로 자동 감지하며 필요하면 수동으로 지정할 수 있습니다. 이 레이어는 지도의 어느 배경지도(OpenStreetMap/Esri/Google/오프라인 캐시)를 선택하든 항상 그 위에 겹쳐 보이도록 렌더링 순서를 고정해두었습니다. **이 프로그램과 타일 폴더가 같은 컴퓨터에 있어야 하며**(경로는 서버가 직접 읽습니다), `run.bat`으로 개인 PC에서 실행하는 일반적인 사용 방식에 맞춰진 기능입니다. 타일링 자체(원본 GeoTIFF → 타일 폴더 변환)는 이미 잘 검증된 QGIS/GDAL에 맡기고, 이 프로그램은 그 결과물을 서빙만 합니다.
78. **선택적 보정 옵션 기본값 변경** — "IMU 흔들림(스웨이) 검출", "헤딩효과 캘리브레이션 보정", "헤딩(비행방향) 보정" 세 옵션은 데이터 특성에 따라 필요할 수도 불필요할 수도 있는 선택적 보정이라, 자료 처리 시 기본값을 체크 해제(미적용) 상태로 바꾸었습니다 - 필요한 경우에만 직접 체크해서 켜세요.
79. **주변 INTERMAGNET 관측소 자동 선택 + 결합 베이스 자료 추정** — 항목 75의 단일 관측소 지정 방식에 더해, 관측소 코드를 몰라도 조사지역 주변 관측소를 자동으로 찾아주는 모드를 추가했습니다. 드론 자료의 평균 좌표(또는 직접 입력한 좌표)를 기준으로, 국가 중심좌표로 대략 추린 후보들을 실제로 하나씩 받아와(각 관측소가 IAGA-2002 파일 헤더에 스스로 보고하는 위경도가 언제나 정확한 최신 정보이므로, 별도로 관측소 좌표표를 관리하지 않고 매번 그 자리에서 확인합니다) 동서남북 4개 방위 중 아직 선택되지 않은 방위에서 가장 가까운 관측소를 우선 고르는 방식으로 방향이 한쪽에 몰리지 않게 관측소를 선정합니다. 선택된 관측소들의 총자력(F) 자료는 거리의 제곱에 반비례하는 가중치로 결합(역거리가중, IDW)해 조사지역에 대한 하나의 가상 베이스 자료로 만듭니다(일변화 보정은 절대 수준이 아니라 변화량만 사용하므로 관측소 간 절대 자기장 차이는 자동으로 상쇄됩니다 - 항목 75와 동일한 원리). 관측소 목록·거리·방위각이 담긴 미리보기를 확인한 뒤 "이 자료를 베이스 자료로 사용"으로 확정하며, 결합된 자료는 CSV 파일로도 내려받아 보관하거나 다른 프로젝트에서 참고할 수 있습니다. "📊 주변 관측소 자료와 비교 그래프 보기" 버튼을 누르면, 계산에 사용된 각 관측소의 실제 원본 자료(색선)와 그로부터 만들어진 결합 추정 자료(굵은 검은 선)를 같은 시간축 위에 겹쳐 그려주어, 추정치가 실제 관측소들의 변화 패턴을 잘 따라가는지 눈으로 확인할 수 있습니다 — 이 비교는 "이 자료를 베이스 자료로 사용"으로 확정하기 전은 물론, 이미 적용한 뒤에도(새로 다시 조회하기 전까지) 계속 볼 수 있습니다. *(참고: 사용자가 제공한, 소스코드 없는 INTERMAGNET 자료 다운로드 프로그램을 안전하게 정적 분석[실행하지 않고 문자열만 조사]한 결과, 이 프로그램은 우리 앱이 이미 사용 중인 것과 같은 공개 BGS GIN 웹 서비스를 그대로 호출하는 것으로 확인되어 별도 연동상 이점은 없었지만, 그 과정에서 우리 앱의 자동 다운로드 요청 파라미터에 있던 실제 버그[관측소별 초당 표본수를 숫자가 아닌 문자열로 잘못 보내던 것]를 발견해 함께 수정했고, 관측소 코드·이름·소속 국가 목록도 확인해 후보 축소에 활용했습니다.)*
80. **INTERMAGNET 조회 날짜를 측선 자료에서 자동 인식 + 결측일 자동 추정** — 항목 75/79의 두 INTERMAGNET 다운로드 옵션(단일 관측소 지정, 주변 관측소 자동 선택) 모두 이제 기본값이 "측선 자료 날짜 자동 사용"입니다: 드론 자력 자료(GPS 시각 기준)를 업로드해 두면 그 자료에 실제로 촬영된 날짜들만 정확히 인식해(예: 7/15, 7/16, 8/3, 8/4, 8/5처럼 몇 주 간격으로 떨어진 며칠만 비행한 조사라면 딱 그 날짜들만) 자동으로 받아옵니다 — 예전처럼 "시작일~종료일" 범위 전체(중간의 관련 없는 3주치 포함)를 통째로 받아올 필요가 없습니다. INTERMAGNET도 같은 GPS/UTC 기준 시각을 쓰므로 시간대 변환 없이 날짜가 그대로 대응됩니다. 필요하면 "직접 기간 지정"으로 전환해 시작일·종료일을 손으로 입력하는 이전 방식도 그대로 쓸 수 있습니다(드론 자료가 아직 없거나 다른 기간의 자료가 필요할 때). 요청한 날짜 중 BGS GIN에 아직 게시되지 않았거나(최근 1~2일치 정식 자료는 흔히 지연됩니다) 특정일의 자료가 통째로 빠진 경우, 그 날짜 바로 전날·다음날 자료만 따로 받아와 분(minute) 단위 패턴으로 추정해 채웁니다(조사 구간 내 멀리 떨어진 다른 날짜의 자료가 섞여 들어가지 않도록, 오직 그 날의 이웃 날짜만 사용). 단순 직선 보간이 아니라 이웃한 실측일의 일변화 굴곡 모양을 그대로 따르고, 정상 자료가 있으면 그 수준에, 없으면 이웃일의 수준에 맞춰 평행이동합니다. 어떤 날짜가 추정되었는지는 미리보기와 비교 그래프(항목 79)에 항상 표시됩니다.
81. **지도에서 클릭으로 지점값 확인** — 그리드를 생성한 뒤(원본 그리드든 RTP/1VD 등 파생 그리드든) "9. 그리딩" 영역의 "지점값 확인" 버튼을 누르면 지도 클릭으로 값을 읽는 모드가 켜집니다(버튼을 다시 누르기 전까지 계속 켜져 있습니다). 이 모드에서 지도를 클릭할 때마다 그 정확한 지점의 값을, 화면에 표시되는 컬러맵과 완전히 같은 값이 나오도록(가장 가까운 실측점이 아니라 실제로 그려진 격자면을 그 지점에서 양선형 보간) 계산해 클릭한 자리에 바로 붙여 보여줍니다 — RTP/RTE/상방연속/추세면제거처럼 여전히 nT 단위인 파생그리드는 nT로, 1VD/dX/dY/AS/THDR처럼 미분 계열인 파생그리드는 nT/m로, 2VD/dXX/dYY/dXY/dXZ/dYZ는 nT/m²로, 틸트각·세타맵은 도(°)로 — 현재 지도에 표시 중인 값이 정확히 무엇이고 어떤 단위인지 함께 표기됩니다(원본 자력이상/TMI를 보고 있을 때 클릭하면 nT 값이, RTP를 보고 있을 때 클릭하면 RTP 변환값이, 1VD를 보고 있을 때 클릭하면 1VD 변환값이 나오는 식으로 항상 현재 화면에 표시 중인 그리드를 기준으로 계산됩니다). 여러 지점을 계속 클릭하면 그 값들이 모두 동시에 지도 위에 남아 있어 서로 비교할 수 있고, "지점값 확인" 버튼을 다시 누르면 전부 지워지며 모드도 꺼집니다(새 그리드/파생그리드를 생성해도 표시 중이던 값들이 이전 그리드 기준이라 자동으로 지워집니다). 자료가 없는 위치(격자 범위 밖이거나 그 위치에 실측 자료가 없어 비어 있는 셀)를 클릭하면 "자료 없음"으로 표시됩니다.
82. **거리/면적 측정 도구** — 오른쪽 패널 "17. 거리/면적 측정"에서 "거리 측정" 또는 "면적 측정" 버튼을 누르면 지도 위에 그리기 도구가 나타납니다(leaflet-draw 도구모음의 선/다각형 아이콘을 눌러 시작). 거리 측정은 지도를 순서대로 클릭해 경로를 그리고 더블클릭으로 마치면 그 경로의 총 길이(지구 곡률을 반영한 대권거리 합)를 지도 위 그려진 선의 가운데에 표시하며, 면적 측정은 다각형을 그리고 마치면 그 다각형이 감싼 면적(조사지역 규모에서 오차가 1% 미만인 지역 평면투영 기반 계산)을 다각형 중심에 표시합니다 — 자력 이상대의 길이나 넓이를 지도에서 직접 재는 용도입니다. 값이 1km/1ha 이상이면 자동으로 km/km²·ha 단위로 바뀌어 표시됩니다. 측정은 여러 번 연달아(선을 하나 그린 뒤 바로 다음 선을) 계속할 수 있고, 모두 지도 위에 동시에 남아 서로 비교할 수 있으며 오른쪽 패널 목록에서도 각 측정값을 확인·개별 삭제할 수 있습니다. "거리 측정"/"면적 측정" 버튼을 다시 누르면 그리기 모드만 꺼지고 이미 그려둔 측정 결과는 그대로 남으며, "전체 지우기"를 눌러야 모두 지워집니다.
83. **초기 로딩 속도 개선 + 워크플로 단계 클릭 이동** — 두 가지를 점검해 고쳤습니다. (1) 성능: "15. UAV 자력탐사 가이드라인 진단 도구" 아코디언이 실제로는 접혀 있어도(HTML `<details>`는 화면에서만 숨길 뿐 내부 컴포넌트는 그대로 마운트되므로) 안에 있는 파워스펙트럼 차트용 Plotly 라이브러리(약 4.4MB)가 앱을 켤 때마다 아무도 그 메뉴를 펼치지 않아도 매번 다운로드되고 있었습니다 — 코드상으로는 지연 로딩(lazy load) 처리가 되어 있었지만 항상 마운트되는 위치에 있어 사실상 무의미했던 것입니다. 이제 그 아코디언을 실제로 한 번 펼치기 전까지는 내부 컴포넌트가 아예 렌더링되지 않도록 고쳐, 최초 접속 시 내려받는 자바스크립트 용량이 약 5MB에서 약 0.6MB로 줄었습니다(브라우저 네트워크 로그로 직접 확인: 이전엔 켜자마자 4.4MB짜리 청크가 요청됐고, 지금은 그 메뉴를 펼칠 때만 요청됩니다). (2) 사용성: 왼쪽 패널 맨 위 진행 체크리스트(드론 업로드 → 베이스 업로드 → 처리 실행 → 그리드 생성 → 고급분석)가 지금까지는 그냥 보기만 하는 표시였는데, 이제 각 단계를 클릭하면 그 단계에 해당하는 아코디언 섹션이 자동으로 펼쳐지고 그 위치로 화면이 스크롤됩니다 — 17개 섹션이 늘어선 긴 사이드바에서 다음에 눌러야 할 버튼을 매번 스크롤해 찾을 필요가 없어졌습니다.
84. **측선 사이 그리딩 공백 보정 (측선 간격이 국지적으로 불균일할 때)** — 그리드/컬러맵에 셀 크기를 작게(측선 간격의 1/5 이하로) 잡아도 측선과 측선 사이 어딘가가 채워지지 않고 배경지도가 비쳐 보이는 문제를 고쳤습니다. 원인은 "이 지점이 실제 자료로부터 너무 멀어 보간하지 않고 빈칸으로 둘지" 판단하는 기준(허용 거리)이 지금까지 프로젝트 전체의 평균 측선 간격 하나로만 계산되었기 때문입니다 — 측선이 완전한 직선이 아니라 약간 휘거나 비뚤어졌거나, 특정 구간만 다른 곳보다 넓게 벌어져 비행된 경우 그 지점의 실제 간격은 전체 평균보다 훨씬 넓은데도 평균값 기준의 좁은 허용 거리에 걸려 채워지지 않는 공백이 생겼습니다. 이제 격자의 각 지점마다 실제로 가장 가까운 두 측선까지의 거리를 따로 계산해 그 지점의 진짜 국지적 간격을 기준으로 채울지 판단합니다(전체 평균이 아니라 그 지점 주변 실측 자료를 그대로 사용하므로 휘거나 간격이 불균일한 측선에도 정확히 대응). 실측 샘플 자료로 확인한 결과 이전에는 셀 크기 2m 기준 격자의 0.8%가 불필요하게 빈칸으로 남았던 것이 이번 수정으로 100% 채워졌으며, 측선 간격이 실제로 크게 들쭉날쭉한 조사에서는 개선폭이 더 클 것으로 예상됩니다. "보간 반경(m)"을 직접 수동으로 지정한 경우에는 그 값을 그대로 존중하며(이 자동 개선의 대상이 아닙니다), 비워두고 자동 계산에 맡긴 경우에만 적용됩니다.
85. **지상구조물 왜곡 자동탐지 (OpenStreetMap + 신호분석 복합)** — 오른쪽 패널 "7-1. 지상구조물 왜곡 자동탐지"에서 실행하면, 건물·도로 등 지상구조물로 인한 자력 왜곡을 하나하나 수동으로(정사영상 보며 폴리곤을 직접 그려 스무딩) 처리하지 않고 자동으로 찾아 일괄 처리할 수 있습니다. 서로 독립된 두 판단을 함께 사용합니다: (1) 위치 근거 — 조사구역의 OpenStreetMap 건물·도로 데이터를 자동으로 내려받아, 각 건물/도로 외곽에서 지정한 반경(기본 건물 10m, 도로 6m)까지를 왜곡 영향권으로 간주하고 겹치는 영역은 하나로 합칩니다. (2) 신호 근거 — 기존 "근지표 표적탐지"(다이폴 피팅)와 같은 원리로 자력이상도에서 국지적으로 뾰족한 이상치를 자동으로 찾아냅니다. 두 결과를 겹쳐봐서, 신호로 찾은 이상치가 지도상 매핑된 구조물 위치와 실제로 일치하면 "구조물 매칭"(왜곡일 가능성이 높음)으로, 일치하는 구조물이 지도에 없으면 "미매칭"(실제 지질이상일 수 있으므로 직접 확인 필요)으로 구분해 표시합니다. 결과는 지도 위에 영역(반투명 다각형)과 이상치(점)로 함께 표시되며, 각 항목을 개별적으로 선택/해제할 수 있는 목록도 함께 제공됩니다 — 매핑된 구조물 영역은 기본적으로 모두 선택되어 있고, 매칭되지 않은 이상치는 기본적으로 선택 해제되어 있어(직접 확인 후 선택하도록) 안전한 기본값을 유지합니다. 선택을 마친 뒤 "선택한 N개 영역 왜곡 스무딩 일괄 적용" 버튼 하나로, 기존 "왜곡 영역 스무딩" 기능(항목 참고: 7. 수동 측선 편집)이 모든 선택 영역에 대해 한 번에 적용됩니다 — 여러 폴리곤을 하나씩 그릴 필요가 없습니다. *(참고: OpenStreetMap Overpass API에 실시간으로 접속하는 기능이므로 인터넷 연결이 필요하며, 폐쇄망/사내망처럼 외부 접속이 막힌 환경에서는 실패할 수 있습니다 — 이 경우 항목 7의 수동 도구를 대신 사용하세요.)*
86. **그리딩 속도 개선 + 측선 바깥으로 무한정 확장되던 외삽 버그 수정** — 항목 84(측선 사이 그리딩 공백 보정)를 넣은 뒤 그리딩이 느려지고, 조사구역 바깥으로 삼각형/부채꼴 모양의 이상한 색이 넓게 번져 나가는 문제가 있었습니다. 원인은 그 항목의 "국지적 측선 간격" 계산 방식 자체에 있었습니다 — 어떤 지점이 실제 측선에서 아주 멀리(예: 측선이 끝난 지점 바깥쪽) 떨어져 있으면, 그 지점에서 "가장 가까운 두 측선까지의 거리"가 둘 다 그 지점이 측선에서 멀어질수록 함께 커지기 때문에, "국지적 간격의 60%까지 채운다"는 판정 기준 자체가 거리와 상관없이 계속 통과해버려 사실상 무제한으로 채워지고 있었습니다(부채꼴로 번져나간 이유). 이번 수정에서는 두 가지를 함께 고쳤습니다: (1) 정확성 — 위 판정과 별개로, 실제 측선 자료들이 감싸는 최소 볼록 다각형(convex hull) 바깥으로는 셀 몇 개(기본 2셀) 이상 절대 채우지 않도록 하드 캡을 추가했습니다. 국지적 간격 계산이 뭐라고 나오든 이 상한을 넘을 수 없어 조사구역 바깥으로 번져나가는 현상이 사라지며, 측선과 측선 "사이"의 정상적인 공백 채움(항목 84의 목적)은 그 다각형 안쪽에 있으므로 전혀 영향받지 않습니다(Oasis Montaj/Surfer/ArcGIS류 상용 그리딩 프로그램들이 기본으로 적용하는 것과 같은 방식입니다). (2) 속도 — 국지적 측선 간격은 지점마다 급격히 바뀌는 값이 아니라 완만하게 변하는 값이므로, 격자가 큰 경우(약 4,000셀 초과) 매 셀마다 정확히 계산하는 대신 성긴 격자(가로세로 1/4 밀도)에서 계산한 뒤 원래 해상도로 매끄럽게 확대하는 방식으로 바꿨습니다. 실측 규모와 비슷한 합성 자료(40개 측선, 미세 셀 크기)로 측정한 결과 계산 시간이 약 5배 단축되었습니다(오차는 평균 2m 미만으로 무시할 수준). 실제 조사구역이 정사각형/직사각형이 아니라 오목한(L자 등) 모양이면 이 자동 볼록 다각형 캡만으로는 그 오목한 부분("notch")까지는 걸러내지 못합니다 — 이런 경우를 위한 수동 보완 도구가 항목 87입니다.
87. **표시 경계 수동 지정 (오목한 조사구역 대응)** — 항목 86의 자동 볼록 다각형 캡은 조사구역이 볼록(convex)한 모양일 때는 충분하지만, L자·ㄷ자처럼 오목한 모양의 조사구역에서는 볼록 다각형 안쪽의 빈 "notch" 부분까지 그대로 채워 보여줄 수 있습니다. "9. 그리딩" 영역에 새로 생긴 "경계 그리기" 버튼을 누르면 지도 위에 다각형을 그리는 모드가 켜지고(기존 "왜곡 영역 스무딩"과 같은 그리기 도구 재사용), 다각형을 완성하면 즉시 저장되어 그 이후로는 그리드/파생그리드/등고선/GeoTIFF·XYZ·Surfer 내보내기 등 모든 표시·출력이 그 다각형 안쪽으로만 제한됩니다(자동 볼록 다각형 캡 위에 추가로 겹쳐 적용되는 방식이라 더 좁히기만 할 뿐, 자동 캡보다 넓게 다시 채우지는 않습니다). 지도에는 그려둔 경계가 주황색 점선으로 항상 표시되며, "경계 지우기" 버튼으로 다시 자동 캡 범위로 되돌릴 수 있습니다. 경계를 그리거나 지워도 이미 계산된 그리드 자체는 다시 계산하지 않고 화면에 표시할 때만 빠르게 가려내므로(캐시를 비우지 않음), 여러 번 다시 그려봐도 느려지지 않습니다. 프로젝트 저장/불러오기에도 함께 저장됩니다. 그려둔 경계는 "경계 파일로 저장" 버튼으로 `.json` 파일로 내보내(같은 조사지역을 다시 처리하거나, 같은 경계를 다른 프로젝트에서도 재사용할 때 유용) "경계 파일 불러오기"로 다시 불러올 수 있습니다.
88. **그리드 이미지가 흐릿하게 보여 이상대 위치가 실제 지점값과 어긋나 보이던 문제 개선** — 그리드/파생그리드 색상 이미지와 "지점값 확인" 클릭값이 서로 다른 위치를 가리키는 것처럼 보인다는 제보가 있어, 그리딩 계산·이미지 렌더링·지점값 조회 세 단계 사이에 좌표 오차나 자료 왜곡이 있는지 합성 자료(정확히 어디에 있는지 아는 뾰족한 이상체 하나)로 직접 검증했습니다 — 그리드 배열의 최고값 셀 좌표, 렌더링된 PNG의 해당 픽셀 색상, "지점값 확인"으로 그 지점을 클릭했을 때 반환되는 값이 모두 소수점 이하까지 정확히 일치함을 확인했습니다(좌표 변환·상하 반전·인덱싱 버그 없음). 대신 실제 원인은 화면 표시 방식이었습니다: 브라우저가 그리드 이미지를 지도에 띄울 때 기본적으로 인접 셀끼리 색을 부드럽게 섞어 확대하는데(bilinear scaling), 셀 크기가 수십m인 그리드를 street-level까지 확대해서 보면 이 자체가 진짜 이상대 위치를 시각적으로 뭉개거나 옆으로 번져 보이게 만들 수 있습니다 — 자료나 그리딩 계산 자체는 왜곡되지 않았지만, 화면에서는 마치 어긋난 것처럼 보일 수 있었던 것입니다. 그리드/파생그리드 이미지에 한해(참조 레이어로 올린 정사영상 등은 기존처럼 매끄럽게 유지) 셀 경계가 또렷하게 보이도록 표시 방식을 바꿔, 이제 화면의 색이 항상 그 위치의 실제 값과 정확히 대응합니다. 만약 그래도 이상대가 실제보다 뭉툭하게 보인다면, 이는 "보간 방법"을 "원본 셀(nearest)"로 쓸 때 측선별 보로노이 형태로 나뉘어 보이는 정상적인 특성이거나(더 부드러운 형태를 원하면 선형/스플라인/최소곡률로 전환), "측선방향 평활화" 파장이 실제 이상체 폭보다 넓게 설정되어 뾰족한 이상이 눌린 경우일 수 있습니다(평활화 파장을 직접 좁게 지정하거나 꺼서 비교해 보세요).
89. **그리드 이미지-지점값 어긋남의 진짜 원인(좌표 등록 오차) 발견 및 수정 + 그리딩 빈공간 추가 개선** — 항목 88 적용 이후에도 "빨간(고값으로 보이는) 셀 위를 클릭했더니 오히려 낮은 값이, 그 옆 파란 셀에서는 더 높은 값이 찍힌다"는 훨씬 구체적인 제보가 있어 재조사한 결과, 실제로 진짜 좌표 버그를 찾았습니다: 그리드 이미지를 지도에 배치하는 경계(bounds) 계산이 격자점(각 셀의 중심 좌표) 사이의 범위만 사용하고 있었는데, Leaflet은 그 경계 안에 이미지를 "셀 하나 = 면적 하나"로 늘려서 그리므로 이미지 경계가 셀 크기의 절반만큼씩 양쪽으로 더 넓어야 각 픽셀이 정확한 실제 좌표에 그려집니다(이미 정확했던 GeoTIFF 내보내기의 좌표 등록 방식과 동일하게 맞춤). 이 반 셀 오차 때문에 격자 중앙에서는 오차가 없지만 가장자리로 갈수록 최대 셀 크기의 절반까지 어긋나 있었고, 이전에는 브라우저의 흐림 효과가 이 오차를 시각적으로 가려주고 있다가 항목 88에서 흐림을 없애면서 오히려 더 뚜렷하게 드러난 것입니다 — 이제 정확히 고쳐 이미지와 실제 좌표가 소수점 단위까지 일치합니다. 더불어 "지점값 확인"이 인접 셀과 부드럽게 섞은(양선형 보간) 값을 돌려주던 방식도, 화면에 실제로 칠해지는 방식(셀 하나 = 단색, 경계 또렷)과 맞지 않아 날카로운 경계 바로 옆을 클릭하면 이웃 셀 쪽으로 살짝 치우친 값이 나올 수 있었던 점을 고쳐, 이제 클릭한 지점에서 가장 가까운 셀의 값을 그대로(섞지 않고) 반환합니다 — 화면에 보이는 자료 없음(빈 공간)과 클릭 결과도 이제 완전히 일치합니다. 그리딩 빈공간 문제도 함께 점검해, 자동 볼록 다각형 캡(항목 86)의 여백을 셀 2개짜리 고정값 대신 조사 전체의 대표 측선 간격(이미 다른 기능에 쓰이는 안정적인 값)에 비례하도록 넓혀, 측선이 완전한 직선이 아니라 살짝 휘거나 굽은 구간에서 실제로는 측선 사이에 있는데 볼록 다각형 캡이 너무 타이트해 빈칸으로 남던 부분이 채워지도록 개선했습니다(항목 86에서 고친 "무한정 확장" 문제는 여전히 방지됩니다 — 이 여백은 항상 유한한 값으로 제한됩니다).
90. **항목 88의 "셀 경계 또렷하게" 표시 방식이 부드러운 보간 결과까지 각지게 만들던 문제 수정** — 항목 88에서 그리드/파생그리드 이미지에 `image-rendering: pixelated`를 강제 적용해 셀 경계를 또렷하게 만들었는데, 이후 항목 89에서 좌표 등록(반 셀) 버그 자체를 근본적으로 고치면서 이 강제 각짐 처리는 더 이상 좌표 정확성에 필요하지 않게 되었습니다. 오히려 "선형/스플라인/최소곡률" 등 부드럽게 이어주는 보간 방법을 선택해도 화면에는 항상 각진 셀 격자무늬로만 보이는 부작용이 남아 있었습니다. 이 강제 처리를 제거해, 이제 보간 방법에 따라 실제로 부드럽게(또는 "원본 셀" 선택 시 의도한 대로 각지게) 표시됩니다 — 좌표 정확성은 항목 89의 수정으로 이미 보장되어 있으므로 영향 없습니다.
91. **"그리드상 최댓값 위치"를 클릭으로 정확히 짚기 어려운 문제 → 원클릭 이동 버튼 추가** — "그리드에서 가장 큰 값과 지점값 확인으로 클릭해 본 값이 다르다"는 제보를 합성 자료 및 실측 자료로 재검증한 결과, 좌표 등록·렌더링·조회 세 단계 모두 소수점 단위까지 정확히 일치함을 다시 확인했습니다(항목 89에서 고친 버그의 재발이 아님). 실제 원인은 지도를 일반적인 확대 수준에서 보면 그리드 셀 하나가 화면상 1~2픽셀에 불과해, 마우스로 "정확히 최댓값을 가진 그 셀"과 "값이 비슷해 보이는 바로 옆 셀"을 구분해 클릭하기가 사람 손으로는 사실상 어렵다는 것이었습니다(더 깊이 확대해서 클릭하면 정확히 일치함을 확인). 이 클릭 정밀도 문제를 근본적으로 없애기 위해, 오른쪽 패널 범례의 "통계" 표에서 Min/Max 값 옆에 "📍이동" 버튼을 추가했습니다 — 누르면 지도가 백엔드가 계산한 그 그리드의 정확한 최댓값/최솟값 셀 위치로 자동 확대·이동하고, 그 지점에 "지점값 확인" 핀이 자동으로 찍혀 정확한 값을 바로 확인할 수 있습니다. 클릭 정밀도에 기대지 않고 항상 정확한 위치로 이동하므로, 이 버튼으로 확인한 값은 통계표의 Min/Max와 항상 정확히 일치합니다.
92. **베이스 자료로 내보낸 "주변관측소 추정값" CSV를 다시 베이스 자료로 불러오지 못하던 문제 수정** — "INTERMAGNET 주변 관측소 자동 추정"(항목 79) 결과를 "CSV로 파일 저장"한 뒤, 그 파일을 이후 "2. 베이스(일변화) 자료 업로드"의 일반 파일 선택창으로 다시 불러오면 다음 단계로 넘어가지 않는(=업로드가 조용히 실패하는) 문제가 있었습니다. 원인은 베이스 파일 형식 자동인식기가 그동안 두 형식(쉼표구분 오전/오후 CSV, 공백구분 "시 분 초 X Y Z F" 텍스트)만 인식하도록 되어 있었는데, 이 CSV 내보내기 자체는 그와 다른 자체 포맷(`timestamp,mag_nT` 헤더)으로 저장되고 있어 인식기가 이를 어떤 형식으로도 판단하지 못하고 거부했기 때문입니다. 자동인식기가 헤더에서 `timestamp`/`mag` 키워드를 찾아 이 자체 내보내기 형식도 인식하도록 추가해, 이제 한 프로젝트에서 만든 주변 관측소 추정 베이스 자료를 다른 프로젝트(같은 조사지역·시기)의 베이스 자료로 그대로 재사용할 수 있습니다(매번 INTERMAGNET 조회를 다시 할 필요가 없습니다).

"지점값 확인" 클릭 조회는 클릭 좌표를 매번 독립적으로 정확히 재계산하므로 이 문제와 전혀 무관했지만(그래서 이전 검증에서 놓쳤습니다), 화면에 보이는 색 자체는 이 문제 때문에 실제 위치에서 벗어나 그려지고 있었던 것입니다. 이제 그리드/파생그리드/3차원 역산 수평 단면 이미지 모두 축에 나란한 사각형 대신 실제 세 꼭짓점(북서/북동/남서)의 정확한 위경도를 그대로 사용해 이미지를 배치하도록(leaflet-imageoverlay-rotated - 세 기준점으로 회전/기울기까지 표현하는 CSS 아핀 변환 방식) 바꿔, 화면의 색과 "지점값 확인" 클릭 결과가 지역이 넓거나 중앙 경선에서 먼 조사구역에서도 항상 정확히 일치합니다.

97. **측정 포인트와 그리드 색상 스케일 불일치 발견 및 수정** — "그리드 이미지 위에 실제 측정자료를 겹쳐 보면 형상이 크게 다른 부분이 있다"는 제보를 실측 자료로 재현·수치검증한 결과, 실제로 그리드 이미지와 포인트 오버레이가 서로 다른 색상 범위(vmin/vmax)를 쓰고 있었음을 확인했습니다: 그리드 이미지는 기본적으로 그리드 값의 2~98 백분위수를 기준으로 하되 자력이상(anomaly) 값처럼 0을 중심으로 대칭시키는 스케일을 쓰는 반면, 지도 위 포인트 색상은 그와 무관하게 전체 원본 측점들의 단순 최소/최대값 범위를 쓰고 있었습니다 - 실측 자료로 계산해보니 같은 800 nT짜리 값이 포인트 스케일에서는 전체 범위의 약 55% 지점(중간 톤)으로, 그리드 스케일에서는 약 73% 지점(뜨거운 색에 훨씬 가까움)으로 서로 다르게 칠해지는 등, 수치는 같아도 눈에 보이는 색이 두 레이어에서 상당히 다르게 나타날 수 있었습니다. 좌표가 아니라 색상 매핑의 불일치였기 때문에 항목 89/95의 좌표 수정과는 무관한 별개의 문제였습니다. 이제 그리드가 표시되어 있을 때는 포인트 오버레이도 항상 그 그리드와 정확히 같은 vmin/vmax(범례에 표시되는 값과 동일)를 사용하도록 통일해, 두 레이어의 색이 항상 일대일로 비교 가능합니다(단, 그리딩 자체는 보간·평활화 과정이므로 원본 자료보다 다소 부드러워지는 것은 정상입니다 - 색상 스케일이 아니라 보간 자체로 인한 차이라면 "보간 방법"을 "원본 셀(nearest)"로 바꾸거나 "측선방향 평활화"를 끄고 비교해 보세요).
98. **실행 화면에 백엔드 버전(커밋) 표시 추가** — "분명히 고쳐달라고 한 문제가 여전히 재현된다"는 제보 중 다수가 실제로는 `run.bat`이 최신 커밋을 받아오지 못했거나(예: `git pull` 충돌) 프론트엔드가 새로 빌드되지 않은 채 예전 버전이 계속 실행되고 있던 경우로 확인되었습니다. 이제 왼쪽 패널 맨 위 제목 아래에 현재 접속된 백엔드 서버가 실제로 실행 중인 커밋 해시와 날짜가 작게 표시됩니다 - "분명히 고친 문제인데 그대로"라면 가장 먼저 이 버전이 최신인지 확인해 주세요(다르다면 `run.bat`을 다시 실행하거나, `git pull`이 실패하지 않았는지/로컬에 직접 수정한 파일이 없는지 확인하세요).
99. **그리드 셀 크기를 세밀하게(측선 간격의 1/10까지) 줄일수록 측선 사이에 nodata가 생기던 문제 수정** — "측선 간격 50m에서 셀 크기 15m는 빈 곳이 없는데 10m로 줄이면 중간중간 nodata 영역이 생긴다"는 제보를 실측과 비슷한(살짝 휘어지고 측선마다 시작/끝 지점이 조금씩 다른) 합성 자료로 재현했습니다. 원인은 자동 보간 반경 계산식(항목 221 참고 - 두 최근접 측선까지의 국지적 간격에 비례해 채울지 판단)의 배율(0.6)이 이론상 필요한 최소값(0.5)보다 겨우 조금 여유 있는 수준이었기 때문입니다: 완벽하게 평행하고 곧은 이상적인 측선이라면 0.6배로도 충분하지만, 실제 측선은 약간 휘거나 흔들리고 측선마다 길이가 조금씩 달라서 이 여유값을 종종 넘어섰고, 셀이 작을수록(격자점이 훨씬 촘촘해질수록) 그 경계에 걸리는 지점이 우연히 격자점과 맞아떨어질 확률이 높아져 - 같은 실제 빈틈이라도 성긴 격자에서는 우연히 격자점이 비껴가 안 보이다가 촘촘한 격자에서는 격자점이 정확히 그 자리에 찍혀 "중간중간" nodata로 나타났던 것입니다. 배율을 넉넉하게(1.2배) 올려 이런 실측 자료의 정상적인 굴곡·불균일에도 여유가 있도록 했고, 실제 실측 샘플 자료(측선 간격 약 98m)로 1/4~1/10 배율 전 구간에서 nodata가 0%임을 확인했습니다(무한정 확장되던 옛 버그(항목 86)를 막는 볼록 다각형 캡은 이 배율과 무관한 별도의 상한이라 함께 재검증했고 여전히 정상 작동합니다).
100. **반복비행 중복 측선 자동 선택** — 특정 이유로 같은 측선 경로를 실수로(또는 재비행 목적으로) 2번 이상 겹치게 비행하는 경우가 있는데, 이렇게 겹치는 두 측선을 자동판별(항목 4의 측선/턴 구분과는 별개로, PCA로 측선 방향을 구해 방향·수직거리가 서로 매우 가까운(기본 8m·15˚ 이내) 측선 쌍을 찾는 방식 - 반복측선 분석(항목 138)에 쓰던 것과 같은 그룹핑 로직을 공유하되, 정상적인 측선 간격(보통 수십 m 이상)과 혼동하지 않도록 더 엄격한(좁은) 허용오차를 기본값으로 씁니다)한 뒤, 겹치는 구간에서 4차 차분 노이즈 지표(항목 134의 QC 채널과 동일한 기준 - 낮을수록 흔들림이 적고 매끈함)로 두 측선의 품질을 비교해 더 나은 쪽만 남기고 나머지 측선은 겹치는 구간만(측선 전체가 아니라) 자동으로 제외합니다. 측선 방향/터닝 판별(항목 4) 이후, 그리고 조사구역 전체의 대표 측선 간격 추정(항목 89/99에 쓰이는 통계) 이전에 실행되도록 순서를 맞춰, 이미 제외된 흔들림 구간이 품질 비교를 왜곡하거나 곧 제외될 중복 측선이 측선 간격 추정치를 왜곡하는 일이 없도록 했습니다. 기본은 꺼짐이며, "4. 이착륙/비측선 구간 판별" 단계에서 켜고 허용오차(수직거리/방향)를 조정할 수 있고, 처리 완료 후 몇 개의 중복 쌍이 발견되어 몇 개의 포인트가 제외되었는지 요약에 표시됩니다.

102. **격자 신뢰도(불확도) 레이어** — 그리드/이상값 표시가 "자료 있음(색칠)" vs "자료 없음(빈 공간)"의 이분법이라, 색칠된 영역 안에서도 실제 측점 바로 위처럼 잘 구속된 곳과 두 측선 사이 보간에 크게 의존한 곳을 구분할 수 없던 한계를 보완했습니다. "9. 그리딩" 섹션에 "격자 신뢰도 레이어 계산" 버튼을 추가해, 각 셀이 실제 자료점으로부터 얼마나 가까운지(항목 99의 nodata 판정에 쓰이는 것과 동일한 기준 거리 대비 비율)를 0(보간 한계 지점)~1(자료점 바로 위)의 연속값으로 계산하고, 초록(신뢰 높음)~빨강(보간 의존)의 색으로 지도 위에 별도 레이어로 겹쳐 표시합니다(불투명도 고정 0.7, 체크박스로 켜고 끌 수 있음). nodata로 마스킹되는 경계와 정확히 일치하도록(같은 내부 계산 로직을 공유) 만들어, 두 레이어가 서로 모순되는 일이 없습니다.
103. **표준 QC 인증서 자동 생성** — 이미 개별적으로 흩어져 있던 QC 지표들(항목 134의 4차 차분 노이즈, 샘플링 간격 QC, 파일간 DC 레벨 오프셋, 헤딩효과 캘리브레이션 교차검증, 반복측선 분석, 자동 제외 비율)을 사용자가 지정한 허용기준과 비교해 항목별 PASS/FAIL/평가불가와 종합 결과를 보여주는 "14-1. 표준 QC 인증서" 패널을 추가했습니다. 각 지표는 원래 계산되는 시점의 채널·기준을 그대로 재사용하며(값을 새로 계산하지 않음), 반복측선 재현성처럼 사용자가 별도로 실행해야 하는 지표는 실행 전이면 "평가 불가"로 정직하게 표시됩니다(PASS로 오인되지 않도록). 허용기준(노이즈 배수, 반복측선 1-sigma, 샘플링 간격 초과비율, 자동제외비율)은 모두 조정 가능하며, 처리 보고서(.md) 다운로드에도 같은 표가 포함됩니다.
104. **대용량 실측 자료(2개 압축파일, 40개 비행파일, 54만여 포인트, 3주 분량)로 실전 처리 후 발견한 성능 병목 2건 수정** — 해남 지역 실측 드론자력 자료(압축파일 2개, 측선 99개)로 전체 파이프라인을 처음부터 끝까지 돌려보며 효율성을 점검한 결과, IGRF 보정과 그리딩 두 단계가 예상보다 훨씬 느리다는 것을 발견했습니다. ① **IGRF 보정**: 내부에서 쓰는 `ppigrf` 라이브러리가 지점 수에 비례해서가 아니라 그보다 훨씬 가파르게 느려지는 특성이 있어(1,000점 이하는 0.02~0.04초인데 9만 점은 6초 가까이 걸림), 54만 점 전체를 한 번에 계산하면 30초 이상 걸렸습니다. IGRF 자기장은 수십~수백 km 규모로만 완만하게 변하는 값이라는 점을 이용해, 날짜별로 작은(10×10×5) 성긴 격자에서만 직접 계산한 뒤 실제 측점들에는 보간(trilinear)으로 채우도록 바꿔, 오차 0.001 nT 미만을 유지하면서 약 7배(35.9초→4.4~5.3초) 빨라졌습니다. ② **그리딩**: 측선이 유난히 많은(99개) 자료에서 측선별 최근접자료 검색이 그리딩 시간의 대부분(9.6초/13.5초)을 차지하고 있어, 이 검색을 CPU 전체 코어에 병렬화(`workers=-1`)해 그리딩 단계도 약 1.8배(12.8초→7.0초) 빨라졌습니다. 두 수정 모두 계산 결과값 자체는 손대지 않는 순수 성능 개선이라, 수정 전/후 파이프라인 출력(측선 수, 제외 자료 수, 그리드 통계)이 완전히 동일함을 확인했습니다.
105. **자력 리니어먼트(구조선) 추출 + 로즈다이어그램** — 광물자원탐사에서 자력 자료로 단층·전단대 등 구조계를 파악하는 데 쓰이는 기법입니다. THD(총수평미분)/AS(analytic signal)/틸트각/1VD 중 원하는 파생 그리드에서 능선(ridge, 국소 극댓값이면서 지정 백분위수 이상인 셀)을 찾아, 서로 가까운 능선 점들을(래스터 상 8-방향 인접이 아니라 실제 거리 기준으로) 하나의 리니어먼트로 묶고 주향(strike, PCA 주축 방향)을 계산합니다. 결과는 지도 위에 주향에 따라 색이 달라지는 선으로 표시되고, 우측 패널의 "14-3. 자력 리니어먼트 추출 + 로즈다이어그램"에서 길이 가중 로즈다이어그램(주향이 축(180° 주기)이라는 특성을 반영해 180° 대칭으로 그림)과 N-S/NE-SW/E-W/NW-SE 4분면별 개수·총길이·비율 표를 함께 볼 수 있습니다. 합성 자료(45° 방향 접촉면)로 검증했을 때 실제 방향을 정확히 복원했고, 해남 실측 자료에서는 59개의 리니어먼트가 추출되며 방향별 분포를 확인했습니다.
106. **빠른 심도추정 도구 3종 추가 (틸트각/Analytic signal/스펙트럼)** — 3차원 역산이나 오일러 디컨볼루션까지 가지 않고도 개략적인 소스 심도를 빠르게 훑어볼 수 있는 도구들을 "14-4. 빠른 심도추정" 패널에 추가했습니다. ① **틸트각 심도추정(Tilt-depth, Salem et al. 2007)**: 틸트각이 0°를 지나는 모든 지점에서, 그 지점의 틸트각 기울기(수평 방향 변화율)로부터 등고선 추적 없이 곧바로 심도를 계산합니다(수직에 가까운 접촉면·얇은 판 모델에 정확). ② **Analytic signal 반치폭법(Roest et al. 1992)**: Analytic signal 진폭의 각 극댓값(피크)에서, 진폭이 피크의 절반이 되는 지점까지의 거리(반치폭, HWHM)를 심도로 추정합니다. ③ **스펙트럼 심도추정(Spector & Grant 1970)**: 그리드 전체의 방사평균 파워스펙트럼 기울기로부터 조사구역을 대표하는 단일 평균 심도를 계산합니다(개별 지점이 아닌 앙상블 평균값 — 3차원 역산 메쉬 자동설정에 이미 쓰이던 것과 같은 계산을 재사용). ①·②는 지도 위에 심도(파랑=얕음~빨강=깊음)로 색칠된 점으로 표시할 수 있습니다. 세 방법 모두 합성 자료(30m 깊이 접촉면)로 실제 심도에 가까운 값을 복원함을 확인했고, 해남 실측 자료에서는 세 방법 모두 0.5초 이내에 계산이 끝나며 중앙값 7~10m 수준의 얕은 심도를 보였습니다.
107. **자성 접촉면 탐지 (Magnetic Contact Detection)** — 항목 140의 멀티스케일 엣지 검출(worming)을 재사용하되, THD 능선이 여러 상향연속(upward continuation) 고도에서 얼마나 지속적으로 같은 자리에 나타나는지("영속성")를 기준으로 골라, 리니어먼트 추출(단일 고도의 능선)과는 별개로 지질 접촉면(암체 경계) 후보를 뽑아냅니다(Archibald et al. 1999) — 얕은 노이즈나 국소 소스로 생기는 단일 고도짜리 가짜 능선을, 여러 고도에서 실제로 이어지는 진짜 경계와 구분해줍니다. "14-5. 자성 접촉면 탐지" 패널에서 실행하며, 결과는 영속성(0~1, 노랑=낮음~보라=높음)으로 색칠된 선으로 지도에 표시되어 "12. 참조 레이어"로 지질도 GeoTIFF를 함께 올려두면 실제 지질 경계와 바로 비교해볼 수 있습니다. 합성 접촉면 자료와 해남 실측 자료 양쪽으로 검증했습니다(해남 자료에서 130개 구간, 총 길이 약 16.6km 추출, 계산 시간 약 9초).
108. **프로스펙티비티 분석 (광물 타깃 스코어링)** — 이 프로그램이 실제로 계산할 수 있는 레이어(ASA, THD, 위 항목의 접촉면·리니어먼트 인접성, 3차원 역산을 실행했다면 천부 감수율)만을 각각 0~1로 정규화한 뒤 가중합산해 종합 점수(Target Score) 그리드를 만들고, 임계값 이상인 극댓값 지점을 순위·설명과 함께 타깃으로 추출합니다 — 지질도·방사능 등 이 프로그램이 취득하지 않는 외부 자료 기반 레이어는 포함하지 않으며, 발표된 광상모델을 그대로 구현한 것도 아니고 자철석/철광·스카른·Ni-Cu-PGE 세 프리셋은 위 레이어들에 대한 가중치 배분(각각 자력 반응 자체, 접촉면 인접성, 구조교차부 인접성 위주)일 뿐임을 분명히 해둡니다 — 사용자 지정 가중치도 선택할 수 있습니다. "14-6. 프로스펙티비티 분석" 패널에서 실행하며, 지도에는 타깃 지점(TARGET 01, 02...+점수)과 종합 점수 레이어를 함께 표시할 수 있고, 각 타깃마다 "종합 점수 X.XX = ASA X.XX(기여 XX%) + THD X.XX(기여 XX%) + ..." 형식으로 어떤 레이어가 왜 그 위치를 타깃으로 선정했는지 자동 설명이 붙습니다. 합성 이상체 자료로 실제 이상 위치 근처에 최상위 타깃이 형성됨을 확인했고, 해남 실측 자료로 3개 프리셋 모두 계산 시간 1초 미만에 순위 목록이 나옴을 확인했습니다.
109. **헤딩효과 캘리브레이션·IMU 흔들림 검출을 켠 상태로 해남 실측 자료 재처리 검증** — 항목 186에서 다른 문제 때문에 기본값을 꺼둔 두 옵션을 이번에는 명시적으로 켜고 해남 실측 자료(54만여 포인트) 전체 파이프라인을 다시 돌려, 두 옵션이 켜졌을 때 실제로 무슨 일이 일어나는지 수치로 확인했습니다. **IMU 흔들림 검출**: 자이로+가속도 신호 기준으로 전체 자료의 약 9.0%(49,140개)가 "비정상 흔들림"으로 플래그되었고, 이 중 33,626개가 실제로 추가 제외되어(기존 자동제외 24,453개 → 58,079개, 유효자료 519,592개 → 485,966개) 그리드 통계(평균/표준편차)는 사실상 그대로 유지되면서 흔들림 구간만 정확히 걸러졌습니다. **헤딩효과 캘리브레이션**: 항목 187의 "측선 턴 구간을 자동 캘리브레이션 자료로 활용" 기능이 11,920개의 턴 구간 표본으로 보정 모델을 자동 구성했지만, 5-fold 교차검증 잔차 표준편차가 4.67nT로 허용기준(3.0nT)을 넘어 "캘리브레이션 자체가 신뢰할 수 없다"고 판단해 보정을 적용하지 않고 원본 자료를 그대로 유지했습니다 — 이 조사지역은 자력이상 자체가 강해(그리드 표준편차 약 41nT) 턴 구간에도 실제 지질 신호가 섞여 있었을 가능성이 높고, 이는 버그가 아니라 품질검증이 의도대로 "믿을 수 없는 보정은 적용하지 않는다"를 지킨 결과입니다. 즉 이 조사구역에서는 IMU 흔들림 검출은 켜서 흔들림 구간을 추가로 걸러내는 것이 유효하지만, 헤딩효과 캘리브레이션은 (최소한 턴 구간 자동추출 방식으로는) 적용되지 않으므로 별도의 저경사도 전용 캘리브레이션 비행을 업로드해야 실제로 효과를 볼 수 있습니다.
110. **오일러 디컨볼루션에 등고비행(AGL) 고도 반영 옵션 추가** — "14. 오일러 디컨볼루션"이 지금까지 모든 측점이 하나의 평평한 가상 관측면 위에 있다고 가정해 심도를 계산하고 있었는데("z is defined positive DOWNWARD from the (assumed flat) observation surface at z=0"), 등고비행(지형 따라 고도를 바꿔가며 지표면 기준 일정 고도로 비행)한 자료에서는 이 가정이 실제 지형 기복만큼 심도를 왜곡시킨다는 지적을 반영했습니다. 이제 "등고비행 고도(AGL, m)" 값을 입력하면 드론이 실제로 기록한 GPS 고도(이미 IGRF 보정·3차원 역산에 쓰이던 것과 같은 값)를 각 탐색창의 실제 관측 높이로 반영해(Reid et al. 1990 등에서 쓰는 "draped survey" 방식의 표준적인 1차 보정 — 수직미분 자체는 여전히 평면 가정을 쓰므로 완전한 보정은 아님을 UI에도 명시) 오일러 방정식을 풀고, 결과 심도를 지표면 기준으로 다시 계산합니다(비워두면 기존과 동일하게 평면 기준). 합성 접촉면 자료로 검증한 결과 AGL 보정 없이는 심도가 (AGL+실제 깊이)에 가깝게 계산되던 것이, 보정 후에는 실제 지표면 기준 깊이에 훨씬 가깝게 나옴을 확인했습니다. 실제 해남 자료(AGL 50m로 재계산)에서는 그 차이가 더 뚜렷하게 드러났습니다: 보정 없이는 8,215개의 해가 나오고 평균 심도가 15.1m(비행고도 아래 15m — 즉 지표면보다 35m나 높은, 물리적으로 불가능한 값)로 계산되었지만, AGL을 반영하자 이런 비현실적인 해 대부분이 "심도가 0 이하(지표면 위)"로 자동 걸러지고 실제로 지표면 아래에 있는 36개의 해만 남았으며 평균 심도도 21.4m(범위 5.0~55.1m)로 훨씬 그럴듯한 값이 되었습니다 — 즉 이전까지 오일러 디컨볼루션 결과의 대부분은 등고비행 고도를 반영하지 않아 지표면 기준으로 해석할 수 없는 값이었다는 뜻입니다. 등고비행 조사자료에서는 AGL 값을 입력하고 사용하시길 권장합니다.
111. **3차원 역산 전면 점검: 지형 반영 확인 + 3D 시각화 개선 + 깊이별 셀 크기 최적화(graded mesh)** — "실제로 3차원 모델을 쓰는지, 결과가 평면처럼 보이는 이유가 무엇인지, 단위 셀 크기를 최적화할 방법은 없는지" 점검 요청을 반영해 3차원 역산 기능 전체를 검토·개선했습니다. **(1) 지형 반영 확인**: 역산 메쉬는 DEM(업로드 시) 또는 등고비행 가정 하 드론 GPS 고도로 추정한 지표고도를 기준으로, 각 x/y 기둥에서 그 위치의 실제 지표고도보다 위에 있는 셀을 "비활성(공기)"로 표시해 계산에서 제외하는 방식("active cell masking")을 이미 쓰고 있었습니다 — 이는 UBC-GIF/SimPEG 계열이 지형 기복이 있는 조사에 표준적으로 쓰는 방식(완전히 지형을 따라 휘어진 메쉬 대신, 계단식으로 지형을 표현)이며, 프로그램이 지형을 무시하고 있었던 것은 아니었습니다. **(2) 그러나 실제 발견된 버그**: 3D 뷰의 "SI 연속 컬러링 박스" 모드에서 상단면(top)이 메쉬 전체에서 단 하나의 공유 고도값으로 그려지고 있어서(지형이 마침 그 고도에 있는 곳만 실제 지표면과 일치하고 나머지는 허공이나 암반을 가로지르는 평면이었음), 이 때문에 결과가 평평해 보인 것으로 확인했습니다 — 각 기둥마다 그 기둥의 실제 최상단 활성 셀(지표면 바로 아래 셀)에서 시작해 슬라이더만큼 더 깊이 내려가도록 수정해, 슬라이더를 움직여도 항상 실제 지형 굴곡을 따라가는 "시트"가 표시되도록 고쳤습니다(등고선을 따라가는 3차원 이상대 뷰인 "이상대 블롭" 모드와 수직 단면 뷰는 원래부터 실제 지형 고도를 정확히 반영하고 있었음을 재확인). **(3) 깊이별 셀 크기 최적화(graded/expanding mesh)**: Li & Oldenburg(1996)의 원 논문 및 UBC-GIF MAG3D·SimPEG가 표준으로 쓰는 "core mesh" 방식(지표면 부근은 조사 기하로 실제 해상도를 낼 수 있으므로 얇게, 심부는 신호 감쇠로 어차피 세밀한 구조를 분해할 수 없으므로 두껍게 — 셀 두께가 깊이에 따라 등비수열로 커짐)을 조사해 도입했습니다. 자동설정 시 근접 표층 두께 목표값과 성장률(기본 1.15배/레이어)로부터 필요한 레이어 수를 역산해 계산하며, 사용자가 "메쉬/역산 파라미터"에서 성장률(1.0=균일, 클수록 표층 얇고 심부 두꺼움)을 직접 조정할 수도 있습니다. 해남 실측 자료로 재검증한 결과 자동설정 레이어 수가 4개(균일 60m 두께)에서 16개(표층 4.3m→심부 35.1m로 점증)로 늘어 계산량 상한(활성 셀 9만개) 안에서 근접 표층 해상도가 약 14배 향상되었고, 단면 뷰에서도 훨씬 촘촘한 지형 형상이 나타남을 확인했습니다(growth_factor=1.0 지정 시 기존 균일 메쉬와 완전히 동일한 결과가 나옴을 회귀 테스트로 확인). **(4) 단면 뷰 지표면 라인 강화**: 동서/남북 단면 뷰는 이미 지표면을 검은 선으로 그리고 있었으나(항목 149), 셀이 성긴 구간에서 눈에 잘 띄지 않을 수 있어 선 굵기를 키우고 지표면 위쪽을 흰색으로 채워 "공기"와 "지하"의 경계가 항상 뚜렷이 구분되도록 다듬었습니다. 5개 신규/수정 백엔드 테스트(등비수열 레이어 두께 검증, growth_factor=1.0 하위호환, 경사 지형에서 박스뷰 상단면이 실제로 기울어짐 검증 포함)를 포함해 전체 308개 백엔드 테스트가 통과했고, 브라우저에서 3D 박스뷰가 실제로 기울어진 지형면을 렌더링함을 스크린샷으로 확인했습니다.
112. **3차원 이상대 뷰에 동서/남북/자유선 단면을 동시에 겹쳐 표시** — 상용 지질모델링 소프트웨어(Mira Geoscience GOCAD Mining Suite 등)가 SI 이상대 볼륨과 여러 방향 단면을 한 화면에 함께 도시해 더 입체적으로 지중 상태를 보여주는 방식을 참고해, 기존에 "이상대 블롭" 뷰(임계값 이상만 표시하는 3D 아이소서페이스)와 "박스" 뷰(경계면 4개 벽)로 나뉘어 있던 것을, 블롭 뷰 안에서 임의의 내부 단면을 추가로 겹쳐 볼 수 있도록 확장했습니다. 백엔드에 새 기능 `internal_slice`(메쉬 경계뿐 아니라 내부 임의 위치에서 동서/남북 단면 추출 - 기존 박스뷰의 벽면 추출 코드를 공유 함수로 일반화)와 `path_slice_3d`(자유선 단면을 거리 기준 2D 이미지가 아니라 실제 x/y/z 좌표를 가진 3D 평면으로 반환)를 추가하고, `/inversion/slice_3d` 엔드포인트로 노출했습니다. 3D 뷰 상단에 "동서 단면"·"남북 단면"(각각 위치 슬라이더 포함)·"자유선 단면(마지막으로 그린 선)" 체크박스가 추가되어, 여러 개를 동시에 켜면 이상대 볼륨과 함께 SI 연속 컬러(임계값 없음, 박스뷰와 동일한 색상 기준)로 칠해진 단면들이 같은 3D 장면 안에 함께 표시됩니다. 신규 백엔드 테스트 3개(내부 단면이 경계에서는 기존 박스뷰 벽면과 정확히 일치하는지, 임의 내부 위치가 정확한 행/열을 추출하는지, 자유선 3D 단면이 기존 거리 기준 단면과 같은 값을 갖는지)를 포함해 전체 311개 백엔드 테스트가 통과했고, 실측 자료로 동서/남북/자유선 단면과 이상대 볼륨을 동시에 렌더링해 스크린샷으로 확인했습니다.
113. **3차원 이상대 뷰 시각화 고도화: 반투명 볼륨 + 임의 개수 단면 + 기울기(자유방향) 단면** — 항목 112에서 만든 "볼륨+단면 동시표시" 기능을 GOCAD Mining Suite류 소프트웨어 수준으로 더 다듬었습니다. **(1) 투명도 조절**: 이상대 블롭(아이소서페이스)이 항상 불투명해서 내부 단면이 볼륨에 가려 보이지 않던 문제를 해결하기 위해 투명도 슬라이더를 추가했습니다 — 볼륨을 반투명하게 하면 내부에 겹친 단면들이 함께 보입니다. **(2) 단면 개수 제한 해제**: 기존에는 동서·남북·자유선 각각 1개씩(체크박스)만 켤 수 있었는데, 이제 "+ 동서" 버튼을 여러 번 눌러 서로 다른 위치의 평행한 단면을 동시에 여러 개 추가할 수 있고(참고 이미지의 여러 평행 슬라이스 배치와 동일한 방식), 각 단면은 목록에 개별 행으로 표시되어 위치를 따로 조정하거나 ✕ 버튼으로 개별 제거할 수 있습니다. **(3) 기울기(자유방향) 단면 신규 추가**: 기존에는 특정 방향 단면을 보려면 지도에 직접 선을 그려야 했는데, 이제 "+ 기울기(자유방향)" 버튼으로 메쉬 중심을 지나는 임의의 방위각(0~179°) 단면을 슬라이더만으로 즉시 추가할 수 있습니다 — 백엔드에 새 함수 `azimuth_line`(메쉬의 대각선 길이만큼 뻗는 직선을 주어진 방위각으로 생성)을 추가하고 기존 `path_slice_3d`에 그대로 연결해 구현했습니다. 신규 백엔드 테스트 2개(방위각 0°/90°가 남북/동서 단면과 동일한 값을 갖는지, 어떤 방위각에서도 메쉬 대각선 전체를 가로지르는지)를 포함해 전체 313개 백엔드 테스트가 통과했고, 실측 자료로 반투명 볼륨 위에 동서·남북·기울기·자유선 4개 단면을 동시에 추가해 스크린샷으로 확인했습니다.
114. **3차원 역산에 사전 지질정보(given information) 반영 — 지질도 기반 참조모델** — "지질도/단면이 있으면 역산 품질이 더 좋아지는지, 어떤 정보를 어떤 방식으로 주면 좋은지" 검토 후, 실제로 갖고 계신 자료가 주로 좌표화는 되어 있지만 암상별로 객체화(벡터화)되어 있지 않은 래스터 지질도라는 점을 반영해 구현했습니다. Li & Oldenburg(1996)가 원래 제안한 "참조모델(reference model)" 메커니즘 — 역산을 0이 아니라 사용자가 지정한 배경 자화율을 향해 수렴하도록 정규화하는 표준 기법 — 을 우리 역산에 추가했습니다. **사용 방법**: 지질도 래스터는 기존 "12. 참조 레이어"에 업로드해 지도에 띄우고, "13. 3차원 역산" 안의 새 "지질 정보" 패널에서 그 위에 폴리곤으로 암상 경계를 그리면 자동으로 번호가 매겨진 블록으로 등록되며, 각 블록의 이름과 대자율(SI)을 목록에서 바로 편집할 수 있습니다(단면 정보가 없어 평면 경계가 깊이 방향으로 그대로 이어진다고 가정하는 2.5D 근사). **자동 색상 군집화로 지질도를 바로 활용하는 방식은 검토 후 채택하지 않았습니다** — 지질도는 지도마다 범례 색상이 제각각이고 등고선·기호·범례·축척 등이 같은 이미지에 섞여 있어 자동 분류가 엉뚱한 경계를 지질 경계로 오인할 위험이 커서, 사용자가 최소한 블록 경계를 확인해주는 현재 방식이 더 안전하다고 판단했습니다. **구현**: `invert()`에 참조모델(m_ref) 파라미터를 추가해, IRLS 컴팩트/포커싱 가중치가 절대 자화율이 아니라 "참조모델로부터의 편차"를 기준으로 계산되도록 재정식화했습니다(기존 Woodbury 데이터공간 해법 그대로 유지, `m_ref=None`이면 기존 동작과 완전히 동일함을 회귀 테스트로 확인). 역산 결과 요약에 "지질 정보 반영: 예/아니오 (활성 셀의 N%가 지질 블록 안에 있음)"이 표시되고, 체크박스로 지질 정보 반영 여부를 껐다 켜서 비교할 수 있습니다. 신규 백엔드 테스트 6개(참조모델 미지정 시 기존 동작과 완전히 동일함, 강한 정규화에서 결과가 참조모델에 수렴함, 블록 CRUD API, 역산 API에서 지질 정보가 실제로 반영/비반영됨)를 포함해 전체 317개 백엔드 테스트가 통과했고, 실측 자료로 지질 블록 2개를 그리고 이름·대자율을 수정한 뒤 역산을 실행해 요약에 반영 비율이 정확히 표시됨을 스크린샷으로 확인했습니다.

115. **주변 관측소 비교 그래프를 창별 개별 스케일 5개 패널로 분리** — "주변 관측소 자료 vs 결합 추정 베이스 자료 비교" 그래프가 하나의 공유 좌표축에 모든 관측소 원본 자료 + 결합 추정 자료를 겹쳐 그리고 있었는데, 관측소마다 그 지점의 절대 지구자기장 세기(대략 위도에 따라 수만 nT 단위로 다름)가 크게 달라 한 그래프의 y축 범위가 그 차이에 맞춰지면서 정작 비교하고 싶은 일변화(diurnal, 보통 수십 nT 수준)의 굴곡이 시각적으로 거의 안 보이는 문제를 반영해 개선했습니다. 그래프를 관측소별(최대 4개) + 결합 추정(1개) 총 5개의 독립된 소형 패널로 나누고, 각 패널이 자체 y축 범위로 자동 스케일되도록 했습니다(x축인 경과시간은 모든 패널이 공유해 시간 정렬은 그대로 유지). 이제 각 패널을 나란히 보면 절대 수준 차이와 무관하게 일변화 곡선의 모양(피크/골 위치, 상대적 진폭)을 바로 비교할 수 있습니다. 백엔드 엔드포인트(`get_nearest_intermagnet_comparison`)는 이미 관측소별/결합 자료를 분리해서 반환하고 있어 변경이 필요 없었고, 프론트엔드 `NearestIntermagnetComparisonView.jsx`만 재작성했습니다. `npm run build` 통과 후, 모의(mock) 관측소 응답 4개 + 결합 1개로 Playwright에서 실제 5개 패널이 각자 다른 y축 범위로 렌더링됨을 스크린샷으로 확인했고 콘솔 에러는 없었습니다.

## 실행 방법

### Windows에서 원클릭 실행 (`run.bat`)

매번 `git pull` 하고 백엔드/프론트엔드를 따로 실행하는 대신, 저장소 최상위의 `run.bat` 파일 하나로 전부 처리할 수 있습니다.
`run.bat`을 더블클릭하면:

1. 최신 버전을 자동으로 받아옵니다 (`git pull`).
2. 새 버전이 있을 때만(처음 실행 포함) 백엔드 패키지 설치 + 프론트엔드 빌드를 자동으로 진행합니다 — 변경사항이 없으면
   이 단계는 몇 초 안에 건너뜁니다.
3. 서버를 시작하고, 서버가 실제로 요청에 응답하기 시작하는 순간(최대 1분까지 대기) 기본 브라우저로
   `http://127.0.0.1:8000`을 자동으로 엽니다 (백엔드가 빌드된 프론트엔드까지 함께 제공하므로 별도로 포트 2개를
   띄울 필요가 없습니다). 컴퓨터 성능이나 최초 실행 여부에 따라 서버가 뜨는 데 걸리는 시간이 다르기 때문에,
   정해진 시간만큼 무작정 기다렸다가 여는 대신 실제로 서버가 응답하는지 확인한 뒤에 엽니다 — 그래도 1분 안에
   응답이 없으면 알림창으로 알려줍니다(이 경우 실행창의 오류 메시지를 확인하세요).
4. 실행창을 닫으면(또는 Ctrl+C) 프로그램이 종료됩니다.

**바탕화면 아이콘으로 만들기**: 탐색기에서 `run.bat`을 우클릭 → "보내기" → "바탕 화면에 바로 가기 만들기". 이후에는
바탕화면 아이콘을 더블클릭하는 것만으로 항상 최신 버전이 실행됩니다.

**최초 1회 필요한 것**: [Python 3.11 이상](https://www.python.org)(설치 시 "Add python.exe to PATH" 체크),
[Node.js LTS](https://nodejs.org), [Git](https://git-scm.com)이 설치되어 있고, 이 저장소가 `git clone`으로 한 번
받아져 있어야 합니다. 이후로는 `run.bat` 실행만으로 항상 최신 버전이 자동으로 갱신·실행됩니다.

**브라우저가 아예 안 열리는 경우**: `run.bat` 창에 `Uvicorn running on http://127.0.0.1:8000`이 떴는데도(= 서버는
정상적으로 실행 중인데도) 브라우저가 열리지 않는다면, 서버 준비 여부를 확인하고 브라우저를 여는 역할을 하는
`wait_and_open.bat`(최소화된 별도의 검은 창으로 잠깐 떴다 사라짐)이 실행되지 못했거나 실패한 것입니다. 흔한
원인은 회사/기관 PC에서 설정된 시스템 프록시가 `127.0.0.1`(내 컴퓨터 자신) 접속 요청까지 가로채 실패시키는
경우입니다 — 이 경우 브라우저를 직접 열어 주소창에 `http://127.0.0.1:8000`을 입력하면 바로 접속됩니다(서버
자체는 정상이므로). 이렇게 직접 입력해서 잘 뜬다면 매번 이렇게 여시거나, 위 주소를 브라우저 즐겨찾기에
등록해두세요. 그 외에 `curl`이 없는 아주 오래된 Windows(2018년 이전 버전)라면 자동으로 고정 지연(15초) 후 여는
방식으로 대체되니 조금 더 기다려 보세요.

macOS/Linux에서는 아래 백엔드/프론트엔드 항목을 참고해 직접 실행하거나, `run.bat`의 로직을 셸 스크립트로 옮겨서 써도 됩니다.

### 백엔드

```bash
cd backend
pip install -r requirements.txt
python3 -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

`--reload`를 붙이면 프론트엔드(Vite)처럼 코드가 바뀔 때마다 서버가 자동으로 재시작됩니다 — 매번 터미널에서 껐다 켤 필요가 없습니다. (다만 코드 저장 후 서버가 재시작되는 짧은 순간에는 요청이 실패할 수 있으니, 재시작 로그가 끝난 뒤 새로고침하세요.)

AI 해석 도우미(챗봇, 기능 35)를 쓰려면 백엔드 실행 전에 `ANTHROPIC_API_KEY` 환경변수를 설정하세요. 설정하지 않아도 나머지 기능은 모두 정상 동작합니다.

```bash
export ANTHROPIC_API_KEY=sk-ant-...
```

### 프론트엔드

```bash
cd frontend
npm install
npm run dev
```

브라우저에서 `http://127.0.0.1:5173` 접속 (Vite 개발서버가 `/api` 요청을 백엔드 8000 포트로 프록시합니다).

### 통합 테스트

실제 샘플 자료(`backend/tests/fixtures/`)로 전체 파이프라인을 API 레벨에서 검증합니다.

```bash
cd backend
python3 tests/test_pipeline_e2e.py
```

## 알려진 제약사항

- **대용량 정사영상 폴더 연동**은 서버가 로컬 디스크에서 직접 파일을 읽는 기능이라, 클라우드/공유 서버에 이 프로그램을 배포해 여러 사용자가 원격으로 접속하는 환경에는 적합하지 않습니다(각자의 컴퓨터에 있는 폴더를 서로 볼 수 없음) — `run.bat`으로 개인 PC에서 실행하는 사용 방식을 전제로 합니다. 타일 행 순서(XYZ/TMS) 자동 감지는 `tilemapresource.xml` 파일 존재 여부에 의존하는 휴리스틱이라, 이 파일이 없는 도구로 만든 TMS 폴더는 XYZ로 잘못 판단될 수 있습니다 — 지도에 타일이 위아래로 뒤집혀 보이면 드롭다운에서 수동으로 "TMS"를 선택하세요. 등록한 레이어는 서버 메모리에만 저장되므로(재시작 시 소실) 새로고침 후에는 다시 연동해야 합니다.
- **배경지도 타일**: OSM/Esri/Google 타일은 사용자의 브라우저가 직접 요청합니다(백엔드가 프록시하지 않음). 사내망/방화벽 환경에서 해당 타일 서버로의 아웃바운드가 막혀 있으면 지도 배경이 표시되지 않을 수 있습니다. 이 경우 "오프라인 배경지도" 기능(항목 76)을 사용하면 됩니다 — 단, 최초 타일 다운로드 자체는 이번엔 백엔드 서버가 OSM/Esri 타일 서버로 아웃바운드 요청을 보내야 하므로, 서버가 있는 곳에서 인터넷이 되어야 합니다(다운로드는 미리 한 번만 하면 되고, 이후 현장에서는 캐시된 타일만 쓰므로 인터넷이 필요 없습니다). 또한 타일 캐시는 서버 로컬 디스크(`.data/tile_cache/`)에 저장되므로, `run.bat`으로 실행하는 개인 PC처럼 서버와 사용 위치가 같은 환경에 적합합니다.
- **INTERMAGNET 자동 다운로드**: 이 기능은 백엔드 서버 자신이 BGS INTERMAGNET Global Node(imag-data.bgs.ac.uk)로 아웃바운드 HTTPS 요청을 보낼 수 있어야 동작합니다. 사내망/방화벽/샌드박스 환경에서 해당 호스트로의 접근이 막혀 있으면 "자동 다운로드 시도"/"주변 관측소 탐색"(항목 79)이 실패하니, 이 경우 intermagnet.org에서 직접 받은 IAGA-2002 파일을 "IAGA-2002 파일 업로드"로 올리세요(네트워크 접근이 전혀 필요 없습니다). 또한 원격 관측소 자료는 로컬(측정 지역 고유) 일변화까지는 반영하지 못하므로, 가능하면 실제 현장 베이스 측정을 우선하고 이 기능은 대안으로만 사용하세요. *(참고: 개발 샌드박스 환경 자체의 네트워크 정책상 실제 BGS GIN 서비스 접속을 이 환경에서 직접 검증하지는 못했습니다 — 모의[mock] HTTP 응답으로 관측소 선택·거리/방위 계산·IDW 결합 로직은 전부 테스트했으니, 실제 사용 환경에서 한 번 확인해 주세요.)*
- **베이스 로거 시계 오프셋**: 베이스 자력계가 GPS 시각에 동기화되지 않은 경우가 흔합니다. 처리 요약에 베이스/드론 시간범위가 겹치지 않는다는 경고가 표시되면 "베이스 시간 오프셋(초)" 값을 조정하세요.
- **Google 위성 타일**은 비공식 XYZ URL이라 이용약관(ToS) 상 상업적 대량 사용에는 적합하지 않을 수 있습니다. 정식 서비스에는 Google Maps Platform API 키 사용을 권장합니다.
- 프로젝트 상태는 서버 메모리에만 저장됩니다(재시작 시 소실). 여러 사용자가 동시에 쓰는 배포 환경에는 별도의 영속 저장소가 필요합니다.
- **헤딩 보정**은 정식 캘리브레이션(figure-8) 비행 기반 보정이 아니라, 인접한 반대방향 측선의 조용한 구간을 비교하는 단순화된 추정치입니다. 측선이 2개 미만이거나 모두 같은 방향으로 비행된 경우 자동으로 건너뜁니다.
- 그리딩 보간 반경을 비워두면(자동) 검출된 측선 간격의 0.6~1.5배를 기준으로 계산합니다. 측선 간격이 고르지 않은 조사에서는 "보간 반경(m)" 값을 직접 조정하는 것이 더 정확할 수 있습니다.
- **GeoTIFF 참조 레이어**는 원본 픽셀 격자를 그대로 유지한 채 네 모서리만 위경도로 변환해 사각형 범위로 근사 표시합니다. 좌표계가 정북 기준으로 크게 회전되어 있지 않은 일반적인 경우에는 문제없지만, 회전이 큰 좌표계에서는 약간의 왜곡이 있을 수 있습니다. 업로드 이미지는 브라우저 메모리 문제를 피하기 위해 긴 변 기준 2000px로 축소되어 표시됩니다.
- **타이라인(교차점) 레벨링**은 정식 동시 네트워크 최소자승 조정(모든 측선+타이라인을 함께 푸는 방식)이 아니라, 타이라인 값을 고정된 기준으로 두고 각 측선에 하나의 상수(DC shift) 보정만 적용하는 단순화된 방식입니다. 타이라인 자체의 레벨링 오차가 있다면 그대로 측선에 전파됩니다.
- **오일러 디컨볼루션**은 관측면을 평평한 기준면(비행 고도 일정 가정)으로 단순화하며, 구조지수를 사용자가 직접 선택해야 합니다(자동 판별 없음) - 실제 이상체의 기하와 다른 구조지수를 고르면 심도 추정이 부정확해집니다. 3차원 역산처럼 정밀한 결과가 아니라 빠른 개략적 위치·심도 참고용입니다.
- **처리 보고서**는 PDF가 아니라 Markdown(.md)으로 생성됩니다 — 별도 네이티브 PDF 라이브러리 의존성 없이 어떤 텍스트 편집기에서도 열리고 GitHub 등에서 바로 렌더링되며, PDF가 필요하면 브라우저 인쇄나 pandoc 등으로 손쉽게 변환할 수 있습니다.
- **그래디오미터(듀얼 센서) 자료는 지원하지 않습니다** — 로드맵 섹션에 범위 평가를 정리해 두었습니다.
- **AI 해석 도우미(챗봇)**는 `ANTHROPIC_API_KEY` 환경변수가 설정된 배포 환경에서만 동작합니다. 도구가 실제로 조회하는 것은 이 프로젝트가 처리한 자료(측선 통계, 역산, 오일러 디컨볼루션, 표적탐지, 업로드한 참조 레이어)뿐이며, 인터넷 검색이나 외부 지질/군사 DB 조회는 하지 않습니다 — 최종 해석 판단과 현장 검증은 사용자의 몫입니다.
- **근지표 표적탐지**는 자동/수동 그래디오미터 보정 없이 단일 센서 자료 기준으로 설계되어, 넓은 지역에서는 일변화 잔차나 완만한 지질 배경 변화가 표적 탐지의 잡음원이 될 수 있습니다(그래디오미터 지원은 로드맵의 미구현 항목으로 남아 있습니다 - 장비 구축 후 재검토 예정). 단일 쌍극자 모델은 서로 가까이 묻힌 여러 표적을 하나로 뭉뚱그려 피팅할 수 있고, 비자성 재질(플라스틱케이스 지뢰 등)이나 극소량의 금속만 포함한 물체는 원리상 탐지 대상이 아닙니다.
- **마이크로레벨링(디코러게이션)**은 측선 방향·측선 간격 규모의 파수 성분을 방향성 필터로 완화하는 방식이라, 실제 지질 이상체가 우연히 측선과 나란한 방향으로 길게 늘어서 있고 그 폭이 측선 간격과 비슷하다면 일부 감쇠될 수 있습니다 — 적용 전후 그리드를 비교해 실제 이상체가 약해지지 않았는지 확인하세요. 보정 강도를 낮추면 영향을 줄일 수 있습니다.
- **좌표계 수동 지정**은 EPSG 코드가 유효한 투영 좌표계를 가리켜야 합니다(위경도 지리좌표계 EPSG 코드를 넣으면 처리 중 오류가 납니다). 잘못 입력하면 처리 실행 시 오류 메시지로 안내됩니다.
- **MicroInfinity Mag / SENSYS MagDrone R3 ASC 형식**은 파일 자체에 달력 날짜가 없고(GPS 초/타임스탬프[ms]만 존재), 처리 시점(서버 처리 당일)을 임시 기준 날짜로 사용합니다 — 같은 날 처리하는 베이스스테이션 로그와는 실제 절대시각이 어긋나 일변화 보정이 겹치지 않을 수 있습니다. 가능하면 같은 날 업로드/처리하거나, 이 두 형식은 날짜 정보가 있는 다른 장비 포맷으로 변환 후 사용하는 것을 권장합니다.
- **최소곡률(Minimum Curvature) 격자화**는 감쇠(damped) 반복법으로 구현되어 있어, 다른 방법보다 계산이 다소 오래 걸릴 수 있습니다(그리드 규모에 따라 최대 수백 ms~수 초).
- **비행 경로 편집기**는 DroneMagAdv의 FlightPathDlg를 참고했지만, 기울어진 사각형/평행사변형 선택이나 PCA 가이드 각도 등 고급 선택 도구는 제공하지 않고 팬·확대/축소·축정렬 사각형 자르기(Cut)/복원(Restore)만 지원하는 단순화된 버전입니다.
- **3차원 역산**은 실험적 기능입니다:
  - 관측점을 원시 포인트가 아니라 기존 그리딩 수준(격자 크기 기준 최대 3,000점)으로 축소하고, 메쉬도 활성 셀 기준 최대 70,000개로 제한합니다 - 더 상세하게(격자를 촘촘히, 레이어를 많이) 설정할수록 정규방정식을 여러 번 푸는 비용이 커져 실행 시간이 최대 1~2분까지 늘어날 수 있습니다. 매우 조밀한 역산은 지원하지 않으며, 상한을 넘으면 오류 메시지와 함께 거부됩니다.
  - 조사 영역이 넓으면 이 상한들 때문에 자동/수동으로 설정한 격자 크기가 실제 측선 간격보다 커질 수 있습니다(예: 측선 간격 100m인데 셀 크기 150m) - 이 경우 결과 요약에 경고가 표시되며, 측선 자료가 가진 해상도를 다 살리지 못한다는 뜻입니다. 관심 영역만 남기고 나머지 측선을 수동 제외한 뒤 다시 역산하거나, 자동 설정을 끄고 셀 크기를 직접 낮추면(실행 시간 증가) 더 세밀한 결과를 얻을 수 있습니다.
  - 파라미터를 비워두면(기본값) 측선 간격과 자력이상 그리드의 방사평균 파워스펙트럼 기울기로부터 격자 크기·탐사 심도·레이어 수를 자동 산정합니다. 스펙트럼 심도 추정은 개별 이상체가 아니라 전체 자료의 "특징적인" 평균 심도를 근사하는 통계적 기법(Spector & Grant 1970)이라, 심도가 서로 크게 다른 이상체들이 섞여 있으면 자동값이 최적이 아닐 수 있습니다 - 자동 설정을 끄고 직접 조정하세요.
  - DEM 없이 GPS로 추정한 지형은 등고비행 가정(일정 AGL) 하의 **상대적** 굴곡만 정확하며, 절대 고도 기준은 사용자가 입력한 AGL 값에 의존하는 근사치입니다.
  - UBC 스타일의 자동 베타 쿨링(discrepancy principle) 없이 고정 반복 횟수 + 사용자 조정 "정규화 강도" 배수로 단순화했습니다. 사전정보가 없는 역산 특성상 해가 유일하지 않으며(non-unique), 특히 근지표에 국소적으로 강한 이상이 있는 실제 자료에서는 일부 셀의 자화율이 물리적 상한(SI 1.0, 안전장치용 상한일 뿐 결과를 임의로 제한하지 않습니다)까지 올라갈 수 있습니다 - 이 경우 정규화 강도를 높이거나 표시 임계값을 조정해 확인하세요.
  - 유도자화(induced magnetization)만 가정하며 잔류자화(remanence)는 고려하지 않습니다 - 이 역시 사전정보 없는 역산에서 흔히 쓰이는 표준적 단순화입니다.
  - 자화율 자체의 절대값보다는 **상대적 위치·형태(어디에 이상대가 뭉쳐 있는지)**를 참고하는 용도에 적합합니다.

## 로드맵 (다음 단계로 논의된 항목, 아직 미구현)

- TMI/RTP 이미지에서 비행고도·이상대 크기 입력 기반 간이 심도 추정 등 2D 해석 도구

### 그래디오미터(듀얼 센서) 지원 - 범위 평가 (미구현)

두 개의 자력계를 수직(또는 수평)으로 일정 간격 이격해 장착하고, 두 센서 값의 차이를 측정 간격으로 나눈 **자력 구배(magnetic gradient, nT/m)**를 직접 얻는 방식입니다. 실측 구배는 단일 센서의 전자력값보다 일변화(diurnal) 영향에 훨씬 덜 민감하고(두 센서가 거의 동시에 같은 배경 변화를 겪어 차분 시 상쇄됨), 얕고 작은 이상체의 경계를 더 날카롭게 드러내는 장점이 있어 UXO 탐사나 정밀 고고물리탐사에서 널리 쓰입니다.

지금까지 진행한 개선들과 달리 이 기능은 기존 파이프라인에 파라미터 하나를 추가하는 수준이 아니라, 다음과 같이 여러 층위에 걸친 구조적 변경이 필요해 이번 라운드에서는 구현하지 않고 범위만 검토했습니다:

- **입력 자료 형식**: 현재 `io_/drone_loader.py`는 한 타임스탬프당 자력값 하나를 전제로 합니다. 듀얼 센서는 로거마다 컬럼 구성이 제각각이라(상단Mag/하단Mag 별도 컬럼, 또는 완전히 별도 파일 2개를 타임스탬프로 매칭 등) 새로운 전용 로더와 두 센서 간 시간 동기화 로직이 필요합니다.
- **센서 간 레벨링(사전 캘리브레이션)**: 두 센서는 제작 편차로 서로 다른 base level과 heading 민감도를 가지므로, 비행 전 정지 상태 비교 또는 별도 캘리브레이션 절차로 오프셋을 추정해 빼주지 않으면 구배값 자체가 왜곡됩니다 - 현재의 헤딩/타이라인 레벨링과는 별개의, 센서쌍 특유의 보정 단계입니다.
- **처리 파이프라인 분기**: 일변화 보정(diurnal correction)의 역할이 크게 줄어들거나(구배는 이미 대부분 상쇄) 아예 다른 방식의 보정으로 대체되어야 하며, despike/필터도 두 채널에 동일하게 적용한 뒤 차분해야 위상이 어긋나지 않습니다.
- **시각화**: 그리딩·RTP/RTE/1VD/AS 변환 자체는 구배값에도 동일하게 적용 가능하지만, 등고선 간격·컬러 스케일 기본값(구배는 nT가 아니라 nT/m 단위로 훨씬 좁은 동적범위)을 별도로 다뤄야 합니다.
- **3차원 역산**: 현재 역산의 정반응 커널(`processing/inversion.py`)은 전자력(TMI) 단일 관측값 기준입니다. 구배 자료를 직접 역산하려면 `choclo`의 자기장 텐서(gradient tensor) 커널로 정반응 행렬을 다시 구성해야 하며, 이는 새로운 검증(합성모델 테스트)이 필요한 별도 작업입니다.

요약하면, 그래디오미터 지원은 로더-보정-시각화-역산 전 layer에 걸친 별도 기능 트랙에 가까워 이번 요청 범위(기존 단일 센서 파이프라인의 개선)와는 성격이 다릅니다. 실제 듀얼 센서 원시자료 샘플이 있다면 그 스키마를 기준으로 별도 설계·구현 라운드로 진행하는 것을 권장합니다.
